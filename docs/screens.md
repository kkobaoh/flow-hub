# 画面仕様

画面の中身（何を表示し、何を操作できるか）をまとめます。見た目（デザイン）と画面の実装は、別に作ります。

## 方針

- フロントエンドは **React + TypeScript** で作ります。ほかのサードパーティーのライブラリは、サーバー側と同じく **基本的に使いません**。
- 画面のリアルタイム更新（AGV の位置、メッセージなど）には **SignalR** を使います。ブラウザ側のクライアントは、Microsoft 公式の `@microsoft/signalr`（MIT）を使います。
- 画面から呼ぶ操作は、サーバーの HTTP の窓口を通します。仕様で「画面ができるまでは HTTP の窓口から」としたもの（運転状態の切り替え、搬送の取りやめ）は、画面から同じ窓口を呼びます。

### 画面とサーバーの通信

| 項目 | 決まり |
|---|---|
| 様子の送り方 | サーバーは、画面がつないだとき（つなぎ直したときも）と、様子が変わったときに、**その様子を丸ごと** SignalR で送る（差分は送らない）。様子には **番号** を付け、変わるたびに1つ進める |
| 届いた様子の扱い | 画面は、届いた様子で丸ごと差し替える。**今より古い番号・同じ番号の様子は捨てる**（届く順が入れ替わっても、重なって届いても崩れない）。つなぎ直したあとは、番号にかかわらず届いた様子を使う（サーバーが起動し直すと、番号は1から始まるため） |
| つながりが切れたとき | 画面の下に「サーバーとつながっていません（つなぎ直しています）」の帯を出し、表示は切れる前の様子だと伝える。**つながるまで、操作のボタンは押せなくする**（安全側）。自動で、すぐ・2秒・5秒、そのあとは10秒ごとに、ずっとつなぎ直し、つながったら最新の様子を受け取る。初めてつなぐときも同じ |
| 様子が届く前 | 運転状態は「確かめています」と出し、運転の切り替えは押せない |
| 操作の送信 | HTTP の窓口へ送り、**10秒で応答がなければあきらめる。やり直さない**。応答がない・断られたときは、メッセージで「〜できたかわかりません。表示の運転状態を確かめてください」と知らせる。表示は、送っただけでは変えず、サーバーから届いた様子で変える。送ってから結果が返るまでは、同じ操作を押せない |
| ログイン | 今は、ハブと HTTP の窓口を **ログインなしで開く**（開発用の構成だけで使う）。ログインを作るときに認証を付ける（やることリスト #23） |

| 様子の種類 | 種類（運転状態、AGV）ごとに別々に番号を付けて送る。番号の扱いは、どの種類も同じ |

#### AGV の様子

サーバーは、登録しているすべての AGV の様子（ID、いるパネルと向き、状態、コントロールステータス、キャリアを上げ下げしている途中か、最後に届いた充電残量）を、ID の順にまとめて送ります。

| 項目 | 決まり |
|---|---|
| 印の名前 | マップの AGV の印には、**ID をそのまま** 書く（長ければ、印に収まるように字を小さくする） |
| 状態の言葉 | 待機中 → 待機（標示灯の色で出す）、走行中 → 走行動作中、緊急停止中 → 緊急停止中、異常 → 異常、位置リセットの完了待ち → 位置リセット待ち、未登録 → **位置がわからない**。位置がわからない AGV は、コントロールステータスの切り替えとマニュアル操作では、位置リセット待ちと同じに扱い、一覧では気をつけるものとして上に並べる |
| 位置がわからない AGV | マップの上には描かず、**マップの一番下の外に「位置がわからない AGV」の見出しを付けて、ID の順に横一列に並べる**。向きの印は描かず、点線の枠で描く。押すと、ほかの AGV と同じくカードを開き、位置は「わからない」と出す。全体を収めるときは、この列まで含める |
| マップにないパネル | 届いたパネルが、描いているマップにないときは、画面を落とさず、位置がわからない AGV の列に並べる。カードでは「P9（マップにない）」のように、届いたパネルを出す |
| 充電しているか | AGV からの知らせがないので、**決まるまで出さない**。充電ピンのあるパネルでも、標示灯は黄（待機中）にし、緑（充電中）と紫（充電できていない）は出さない（未決事項 #23） |
| 充電残量 | 交通整理が、最後に AGV から届いた値をメモリに持つ。起動してから一度も届いていなければ「不明」。再起動したら、次に届くまでわからない |
| 割り当て済みの搬送 | カードに「#12 ST-1 から DEV-1 へ」（番号と、受け渡しの相手の名前で搬送元から搬送先）と、今の段階（搬送元へ移動、搬送先で受け渡し中、中断 など）を出す。一時停止中なら、段階に「（一時停止中）」と添える。ものを積んだまま止まっていた AGV 自身が搬送元なら、搬送元はその AGV の ID |
| 予約しているパネル | すべての AGV の予約を描く。**AGV がいるパネルの予約も描く**。どの AGV の予約かは区別しない。描いているマップにないパネルの予約は、そのパネルだけ外して描く |
| 走る予定の経路 | AGV ごとに、今のパネルから **行き先まで**（AGV に渡した区間と、まだ渡していない区間をつないだもの）を描く。走る予定がなければ描かない。描いているマップにないパネルを通る経路は描かない |

#### AGV への操作

AGV のカードからの操作（緊急停止、コントロールステータスの切り替え、アラームクリア、位置リセット、マニュアル操作）は、HTTP の窓口（`/agvs/{AGV の ID}/…`）へ送ります。

| 項目 | 決まり |
|---|---|
| 確かめる画面 | **緊急停止** は、安全のため確かめずにすぐ送る。**保守の操作**（マニュアル・ロック・切り離しへの切り替えと、そこから戻す切り替え、アラームクリア、位置リセット）は、確かめる画面を出してから送る。オートと割り当て停止の間の切り替えと、マニュアル操作は、確かめない |
| 位置の指定 | 位置リセットと、切り離しから戻すときは、確かめる画面で **パネル**（マップのパネルの一覧から選ぶ）と **向き**（0・90・180・270度から選ぶ）を選ぶ。今わかっている位置を、最初から選んでおく。ただし、今わかっている向きが 0・90・180・270度のどれでもないとき（斜めに止まっているなど）と、位置がわからないときは、**向きを未選択** にし、**パネルと向きの両方を選ぶまで決められない**（わからない向きを 0度と思い込んで送らないため）。「AGV を手で十字の上まで動かしてから」と伝える |
| 送っている途中 | 送って結果が返るまでは、その AGV の **緊急停止のほかの操作** を押せない（緊急停止は、いつでも押せる） |
| つながっていないとき | 緊急停止も含めて、押せない（送れないため） |
| 送信 | 10秒で応答がなければあきらめる。やり直さない |
| 断られたとき | カードの中（緊急停止の下）に理由を出す。ほかの AGV が予約しているパネル、今の AGV の状態では受け付けられない、応答がなく届いたかわからない、の3つ。理由は、**その AGV へ次の操作を送ったときに消す**（カードを閉じて開き直しても、それまでは出したまま）。マニュアル操作の結果は、マニュアル操作の欄に出す |
| マニュアルの行き先 | 選べるのは、マップのパネル（ID の順）。特殊消耗品受け渡しパネルを選んだら、着いたときの向きは選ばせず、「着いたら、キャリアを下ろす角度（○°）を向きます」と出す |

- 今、サーバーとつないでいるのは **公開中のマップ（パネルの位置、装置とステーションの外形）、運転状態、AGV の様子（予約、経路、割り当て済みの搬送を含む）、AGV への操作、メッセージ、装置とステーションの様子（マップの札とカードの、気をつけること、ストッカー、在庫）、搬送の一覧の画面、装置とストッカーの画面、ステーションの在庫の画面** です。ほかの画面のデータは、まだ見本のデータです（その画面の上に「この画面は、見本のデータです」の帯を出す）。マップの画面の「消耗品を探す」も、まだ見本のデータです。
- マップの画面は、マップが届くまでは「マップを読み込んでいます」と出し、まだ公開されていなければ「マップがまだ公開されていません」と出す。
- **装置とステーションの気をつけること**（札とカードに出すもの。サーバーが消耗品の管理から数えて送る `equipment`）
  - **不足 N**（装置）：届ける途中のもの（届ける予約をしたもの、受け渡し部にある新品）を引いた、まだ手当てのない数（品種の合計）。不足の判断（domain.md）と同じ数。
  - **回収待ち N**（装置）：回収が要ると判断してから、装置から取り出すまでの数。搬送を頼む前のものも、頼んで AGV を待っているものも数える（設定にない品種、設定より多い品種、廃棄リクエスト、不整合）。
  - **ID 食い違い**（装置）：照合のエラーが来てから、そのスロットが片付くまで（人が交換しても、現物を確かめるために AGV で取り出すまでは残る）。カードには、そのストッカーとスロットを出す。
  - **段取り替えのエラー**（装置）：頼まれた品種がストッカーの設定になかったとき。**その装置のストッカーの設定を変えたときか、次の段取り替えのリクエストが通ったときに消す**。カードには、エラーになった品種を出す。DB には残さないので、起動し直すと消える（上位システムには知らせてある）。
  - **要確認 N**（ステーション）：そのステーションにある、要確認の消耗品の数。
  - **補充待ち N**（ステーション）：補充を頼んで、まだ入っていない数の合計。どのステーションに入るかは決まっていないので、**すべてのステーションに同じ数を出す**（ステーションが複数になったら、入る先を決めるときに見直す）。カードでは、品種ごとの数も出す。

## ログインと権限

ユーザーはログインして使います。ユーザー ID とパスワードは **システムの中に持ちます**。権限は **パーミッション方式** にします。

- **最初の管理者**：最初に起動したとき、ユーザーが1人もいなければ、決まった ID と初期パスワードの管理者を作ります。初めてログインしたときに、パスワードの変更を求めます。
  - 将来は、セキュアバイデフォルトの考え方に寄せて、最初のアカウントは **ユーザーを作ることしかできないアカウント** にします（やることリスト #19）。

### パスワードとログインの決まり

どれも設定で変えられるようにします。

| 項目 | 決まり |
|---|---|
| 長さ | 8文字以上 |
| 文字の種類 | 決まりを設けない（長さで守る） |
| 有効期限 | 設けない（定期的な変更は求めない） |
| ログインの失敗 | 5回続けて失敗したら、15分間ロックする。管理者は、15分を待たずにロックを外せる |
| 自分のパスワードの変更 | ログインしている人が、メニューのユーザー名の欄（ログアウトの横）の「パスワードを変える」から変える |
| ログインしたままの時間 | 操作がないまま一定の時間がたったら、ログアウトする。時間は **ロールごとに設定** する（最初は、閲覧のみが **1週間**、ほかのロールは **8時間**） |
| パスワードを忘れたとき | 管理者が、仮のパスワードに設定し直す（次のログインで変更を求める） |

- ログインしたままの時間をロールごとに分けるのは、操作できるロールでログインしたまま離れると、ほかの人がその権限で操作できてしまうためです。現場に表示しておくだけの端末は、閲覧のみのユーザーでログインします。

- 操作ごとに **パーミッション** を決めます（下の表の各行）。
- **ロール** は、パーミッションの組み合わせです。ユーザーにロールを **1つだけ** 付け、そのロールが持つパーミッションで、使える操作が決まります。
- 最初から、次の4つのロールを用意します。中身は、下の「パーミッションと最初のロール」の表のとおりです。
- ロールは、ユーザーが **追加** できます。
- **管理者のロールは固定** です（中身を変えたり、消したりできません）。ほかの3つのロールと、追加したロールは、中身を変えたり消したりできます。
- ユーザーを追加したときは、**デフォルトのロール** を割り当てます。最初のデフォルトは **閲覧のみ** です（新しいユーザーは見るだけにしておき、必要な操作は改めて許すため）。
  - 管理者は、ほかのロールをデフォルトにできます。
  - デフォルトのロールは消せません（中身は変えられます）。

| 最初のロール | 役割 |
|---|---|
| 閲覧のみ | 見るだけ。操作はできない |
| 運用 | ふだんの運転と、消耗品の取り扱いをする |
| 保守 | AGV を動かす・復旧させる操作と、記録を直接書き換える操作をする |
| 管理者 | 構成（マップ、AGV、消耗品の構成）を変え、ユーザーとロールを管理する |

## 画面の一覧

| # | 画面 | 中身 |
|---|---|---|
| 1 | 全体の様子（マップ） | マップの上に、AGV の位置・向き・標示灯・状態、予約しているパネル、走る予定の経路を描く。**装置とステーション** を実物の大きさで描き（床の下にあるので、受け渡しパネルに重ねて点線で透かして描く）、名前と、気をつけること（装置は不足・回収待ち・ID の食い違い・段取り替えのエラー、ステーションは要確認・補充待ち）の印を出す。押すと、AGV と同じく左からカードが出て、気をつけることの中身、ストッカーの設定（ステーションは品種ごとの数）、その装置やステーションの画面への入り口を表示する。運転状態（スタート／停止）の切り替え。AGV を押すと、左から AGV のカードが出て、詳細（状態、コントロールステータス、位置、搬送、充電残量）と操作（コントロールステータスの切り替え、緊急停止、アラームクリア、位置リセット）をまとめて表示する。マニュアルの AGV は、カードから **マニュアル操作**（行き先の指定、1つずつの動作、キャリアの上げ下げ）を送る。マップの右端のボタンから **一覧** を左に出す。一覧は **AGV・装置・ステーション・消耗品** のタブに分け、どれも検索して選ぶ（一覧の行にマウスを乗せると、マップの上のその場所を目立たせる）。消耗品は ID で探したときだけ並べ、選ぶと、ある場所（装置・AGV・ステーション）をマップで示し、所在と状態をカードに出す。マップの画面は「見つけて、その場で対処する」ところとし、手入力・履歴・細かい設定は、それぞれの画面で行う。マップの右の列に **メッセージ**（「画面で知らせる」と決めたもの）を新しい順に並べ、まだ見ていないものとすべてを切り替えて見る |
| 2 | 搬送の一覧 | 待ち行列、走っている搬送、中断した搬送。取りやめ、やり直し |
| 3 | 装置とストッカー | ストッカーのスロットと中身、加工部の描画、不足・回収の様子。ストッカーの設定（段取り替え） |
| 4 | ステーションの在庫 | ステーションの消耗品。要確認の消耗品の修正、出庫、補充の頼みの様子 |
| 5 | 消耗品の検索と手入力 | 所在と履歴、在庫の手入力（登録・修正・削除）、指名、AGV での交換の指示 |
| 6 | マップの編集 | パネルとつながりの編集、装置とステーションの外形、下書きの保存、検証、公開。キャリアの高さ |
| 7 | AGV と AGV の種類の登録 | 速さ、キャリアの種類、充電の設定値、特殊消耗品受け渡しパネルを走れるか |
| 8 | 消耗品の構成 | 加工の種類、品種、装置、ステーションの登録 |
| 9 | ユーザーとロールの管理 | ユーザーの追加、ロールの付け替え、仮のパスワードの設定、ロックを外す。ロールの追加・削除、ロールごとのパーミッション、デフォルトのロール、ログインしたままの時間 |

## どの画面にも共通の決まり

- **確かめる画面**：元に戻せない操作（運転のスタート・停止、搬送の取りやめ、出庫、記録を消す、ロールを消す、マップの公開、仮のパスワードにする、など）の前には、確かめる画面を出す。入力を保存する、一覧を絞り込むなど、戻せる操作には出さない。確かめる画面を開いたら「やめる」に焦点を置く。

## どの画面にも出すもの

- **上の帯の名前（FlowHub）**：押すと、マップの画面（ホーム）へ移ります。
- **メッセージの列**：どの画面でも、画面の右端のタブで開け閉めします。タブには、まだ見ていないメッセージの件数を出します。上の帯には、メッセージのボタンを置きません。
  - マップの画面では、マップの右に並べて出します。まだ見ていないメッセージがあれば、最初から開いておきます。
  - マップ以外の画面では、最初はたたんでおきます。開いたときは、画面の中身を押し縮めずに、右から重ねて出し、外を押せば閉じます。タブは、スクロールしても動かないように、上の帯のすぐ下に置きます（メニューを開いたときは、メニューの一覧をタブより上に出す）。
  - スマートフォンでは、どの画面でも、画面の下から出します。
  - **持ち方**：メッセージは **サーバーの DB に残し**（`FlowHub.Notifications`）、**新しいほうから 200件** まで残す（件数は設定 `Notifications:Capacity` で変えられる）。つないだときと、増えたときに、残しているもの全部を番号つきで画面へ送る。
  - **出すもの**：搬送の中断、予約が取れずに止まっている、行ける充電ポートがない、マニュアルで並べた動作を止めて捨てた、停止したときに止める場所がなくその場で止めた、起動したときの AGV の登録の食い違い（交通整理と配車の片方にしかない）。ほかの「画面で警告する」ものは、あとで足す（backlog #10）。
  - **見た**：「まだ見ていない／見た」は **ユーザーごと** に持つ。ログインができるまでは **ブラウザーごと** に、どこまで見たか（メッセージの番号）をブラウザーに覚える。初めて開いたブラウザーでは、残っているものを **すべて「まだ見ていない」** にする。
  - 画面からの操作がサーバーに届かなかったときの知らせ（運転をスタートできなかった、など）は、サーバーに残せないので、**その画面のメッセージの列にだけ** 出し、時刻の順に混ぜて並べる（読み込み直すと消える）。

## パーミッションと最初のロール

各行がパーミッションです。○は、最初のロールがそのパーミッションを持つことを表します。

| パーミッション | 閲覧のみ | 運用 | 保守 | 管理者 |
|---|---|---|---|---|
| すべての画面を見る | ○ | ○ | ○ | ○ |
| 運転状態のスタート・停止 | | ○ | ○ | ○ |
| 緊急停止 | | ○ | ○ | ○ |
| 搬送の取りやめ、中断した搬送のやり直し・取りやめ | | ○ | ○ | ○ |
| コントロールステータス：オート ⇔ 割り当て停止 | | ○ | ○ | ○ |
| ストッカーの設定（段取り替え） | | ○ | ○ | ○ |
| 要確認の消耗品の修正、出庫、指名、AGV での交換の指示 | | ○ | ○ | ○ |
| コントロールステータス：マニュアル・ロック・切り離し（と、切り離しから戻す） | | | ○ | ○ |
| アラームクリア、位置リセット | | | ○ | ○ |
| マニュアル操作 | | | ○ | ○ |
| 在庫の手入力（登録・修正・削除） | | | ○ | ○ |
| マップの編集・公開、AGV と AGV の種類の登録、消耗品の構成 | | | | ○ |
| ユーザーとロールの管理 | | | | ○ |

- 運用は、止める操作（緊急停止）を安全のため使えるようにしています。
- マニュアル・ロック・切り離しの AGV を、ほかのステータス（オートや割り当て停止を含む）へ切り替えるのも、保守の操作です。保守の人が作業している AGV を、運用の人が知らずにオートへ戻して動き出させないためです。運用が切り替えられるのは、オートと割り当て停止の間だけです。

## 画面ごとの目的とやること

それぞれの画面が何のためにあり、使う人に何をさせたいかをまとめます。画面の細かい中身（項目、並べ方、確かめる画面を出すかなど）は、画面ごとに詰めていきます。

### 1 全体の様子（マップ）

- **目的**：床の **いまの様子が一目でわかり**、気になるものを **見つけて、その場で対処する**。運転中にいちばん長く開いておく画面。
- **使う人**：運用・保守（閲覧のみの人は、現場に表示しておく端末で見る）。
- **やること**
  - AGV、装置、ステーションの様子を、実物と同じ見た目と縮尺で見る。
  - 運転状態をスタート・停止にする（確かめる画面を出してから）。
  - AGV を選んで、緊急停止、コントロールステータスの切り替え、アラームクリア、位置リセット、マニュアル操作をする。
  - 装置やステーションを選んで、気をつけることの中身を見る。
  - 一覧から、AGV・装置・ステーション・消耗品を探し、マップの上の場所を見る。
  - メッセージを見て、見たことにする。
- **ここでしないこと**：手入力、履歴を追うこと、細かい設定。それぞれの画面へ移って行う。
- **マップの表示**
  - 最初の表示と「表示の位置を戻す」は、**マップの全体が画面に収まる大きさ** にして、真ん中に置く。
  - 拡大は、パネル1枚が 200px ほどになるまで。縮小は、全体が収まる大きさの半分まで。
  - ドラッグで動かし、マウスのホイールと2本の指でつまむ操作、「＋」「－」のボタンで拡大・縮小する。少し動かしただけ（4px まで）は、ドラッグではなく押したことにする。
- **一覧の並べ方**：AGV・装置・ステーションのタブは、**気をつけるものを上** にし、それぞれの中と残りは **番号（ID）の順**（AGV-2 は AGV-10 より前）に並べる。
  - AGV で気をつけるものは、緊急停止中・異常・位置リセット待ちの AGV。
  - 装置とステーションで気をつけるものは、気をつけることの札があるもの。
  - 消耗品のタブは、ID で探したときだけ、合うものを ID の順に並べる。

### 2 搬送の一覧

- **目的**：搬送が **いまどこまで進んでいて、どれが止まっているか** をつかみ、止まったものを片付ける。
- **使う人**：運用・保守。
- **やること**
  - 待ち行列、走っている搬送、中断した搬送を、分けて見る。
  - 搬送を取りやめる。
  - 中断した搬送を、位置リセットのあとに、やり直すか取りやめるか選ぶ。
- **ここでしないこと**：搬送を新しく頼むこと（搬送は、搬送計画が頼む）。
- **タブ**：待ち行列、走っている、中断した、の3つ。タブには件数を出し、中断した搬送の件数は目立つ色にする。
  - 開いたときは、中断した搬送があれば「中断した」、なければ「走っている」のタブを出す。
- **並べ方**：どのタブも **必要時刻が早い順**。必要時刻が同じものは、搬送の番号の順（番号は頼まれた順に付くので、待ち行列では頼まれた順、つまり割り当てる順と同じ）。
- **種類と運ぶもの**：配車は運ぶものを知らないので、**頼んだ側（搬送計画）から聞いた中身** を、搬送の番号で結び付けて出す。種類は、届ける、回収する、届ける（AGV から）、返す（AGV から）。運ぶものは「DR-5 2個、不明な消耗品 1個」のように品種ごとの数で出す。頼んだ側から聞けなかった搬送は、種類を「－」、運ぶものを数だけにする。
- **いまの段階**：割り当て待ち、と AGV のカードと同じ段階の言葉。一時停止中なら、補足に「一時停止中」と出す。
- **操作**
  - 取りやめる・やり直すは、どちらも確かめる画面を出してから送る。
  - 中断した搬送の「やり直す」「取りやめる」は、未決事項 #10（異常時の扱い）が決まるまで作らないので、**どちらも押せなくし**、その理由を出す（backlog #8）。決まったら、「やり直す」は位置リセットが済むまで押せなくする。
  - 取りやめの結果は、一覧の上に出す（次に送ったら消す）。受け渡しの途中で、キャリアを上げたところで止まるとき、搬送先で受け渡しを始めていて最後まで終えるとき、中断したか終わった搬送で取りやめられなかったとき、応答がなかったとき。取りやめたときは何も出さない（一覧から消える）。
  - サーバーとつながっていないときと、送って結果を待つあいだは、取りやめを押せない。
  - 「搬送の取りやめ、中断した搬送のやり直し・取りやめ」のパーミッションがない人には、ボタンを押せなくし、その理由を出す。

### 3 装置とストッカー

- **目的**：装置の中に **何がどこにあるか** と、**足りないもの・回収するもの** をつかむ。段取り替えをする。
- **使う人**：運用。
- **やること**
  - 加工部、ストッカーのスロット、受け渡し部の中身を見る。
  - 不足や回収の様子を見る。
  - ストッカーの設定（品種と個数）を変える（段取り替え）。
- **ここでしないこと**：装置の登録（消耗品の構成で行う）、消耗品の記録の直接の書き換え（消耗品の検索と手入力で行う）。
- **出す装置**：マップの装置のカードから来たときは、その装置。それ以外は、番号がいちばん小さい装置。選んだ装置は URL の # のあと（`#/devices/DEV-2`）に覚え、読み込み直しても同じ装置を出す。選ぶ欄は、番号の順に並べる。
- **装置の中**：加工部、ストッカーごとのスロット、受け渡し部の中身を出す。プレートに載せたまま置くストッカーは、スロットの代わりに、置いてある消耗品を並べる。
  - スロットは、**消耗品がある** か **空き** かだけを出す。届ける途中のもの（入れ先のスロットは、装置で降ろすときに決まる）と、加工部に取り込み中の消耗品の元のスロットは、空きとして出す（届ける途中の数は、マップのカードの「スロット」に出す）。
  - スロットにある消耗品には、品種、ID、新品か中古品かを出す。回収するもの（設定にない、設定より多い、廃棄）は「回収する（わけ）」、回収を頼んだものは「回収を頼んだ」と、目立たせて出す。ID が食い違って現物を確かめるまでふさいでいるスロットは、太い枠で「ID が食い違った」と出す。品種がわからないものは「不明な消耗品」と出す。
- サーバーとつながっていないときは、設定を変えるボタンと保存を押せなくし、その理由を出す。保存を送って結果が返るまでは、もう一度は押せない。
- サーバーが設定を断ったとき（個数の合計がスロットの数を超えている。画面以外から変えるときのために、サーバーも確かめる）は、変えた内容のまま理由を出す。
- **ストッカーの設定**
  - 品種ごとに、設定の個数、ある新品（届ける途中を含む）、状態（足りている、足りない、設定より多い、設定にない）を出す。設定にない品種でも、装置にあれば「設定にない（回収する）」として出す。
  - 設定を変えるときは、品種ごとの個数を入れ、品種を加えたり外したりして、保存する（戻せる操作なので、確かめる画面は出さない）。個数を 0 にした品種は、保存すると設定から外れる。
  - 個数は 0 以上の整数に限る。**個数の合計が、装置のスロットの数を超えたら保存できない**（理由を出す）。プレートに載せたまま置く装置（スロットがない）では、合計を確かめない。
  - 「ストッカーの設定」のパーミッションがない人には、設定を変えるボタンを押せなくし、その理由を出す。

### 4 ステーションの在庫

- **目的**：システムの出入り口にある消耗品を管理し、**要確認の消耗品を片付ける**。
- **使う人**：運用。
- **やること**
  - 品種ごとの数（届けられる新品、届ける予約、補充を頼んでまだ入っていない数）を見る。
  - 要確認の消耗品を、現物を確かめて直す（品種、新品か中古品か）。
  - 消耗品を出庫する。
- **ここでしないこと**：在庫の手入力（消耗品の検索と手入力で行う）。
- **ステーションにある消耗品の並べ方**：**要確認を上** にし、それぞれの中と残りは **ID の順**。「要確認だけ」に絞り込める。
- **ステーションにある消耗品の状態**：届けられる、届ける予約あり（DEV-1 へ）、指名あり（DEV-1）、要確認、出庫を頼んだ、届けない（中古品）。いくつも当てはまるときは、要確認、出庫を頼んだ、届ける予約、指名、の順に1つを出す。入庫した日時も出す。
- **出庫**：確かめる画面を出してから、ステーションに取り出しを頼む。届ける予約や指名が付いていれば、解いて出すことを確かめる画面に書く。
  - 出庫を頼んだものは、押せなくし、その理由を出す。
  - 届ける搬送に AGV を割り当て済みかは、画面では持たないので、押せるようにしておき、**送ってサーバーが断ったら**「届ける搬送に AGV を割り当て済みなので、出庫できませんでした」と出す。ステーションになかったときも、断られた理由を出す。
  - **要確認のものも、直さずに出庫できる**。
- **要確認の消耗品を直す**：品種と、新品か中古品かは、**どちらも未選択から始め、両方を選ぶまで保存できない**（記録に品種があるものも同じ。現物を確かめずに保存しないため）。保存は戻せる操作なので、確かめる画面は出さない。
  - 直す画面には、**要確認になったわけ**（登録されていない ID として入ってきた、所在不明だったものがステーションで見つかった、装置で ID が食い違ったので回収した）を出す。
  - もう要確認でなくなっていたら（ほかの人が直した、出庫したなど）、サーバーが断るので、その理由を出す。
- 断られた理由は、一覧の上に出し、次に操作を送ったときに消す。送って結果が返るまでは、出庫と直すを押せない。サーバーとつながっていないときは、出庫と直すを押せなくし、その理由を出す。
- 「要確認の消耗品の修正、出庫…」のパーミッションがない人には、出庫と直すボタンを押せなくし、その理由を出す。
- ステーションが複数あるときは、装置とストッカーの画面と同じ決まりで出すステーションを選ぶ（`#/station/ST-1`）。

### 5 消耗品の検索と手入力

- **目的**：1個の消耗品について、**今どこにあり、どう動いてきたか** を確かめ、記録が現物と合わないときに直す。
- **使う人**：運用（調べる、指名する、AGV での交換を指示する）、保守（記録を直す）。
- **やること**
  - ID で探して、所在、状態、これまでの動きを見る。
  - 装置へ届けるものに指名する。AGV での交換を指示する。
  - 在庫を手入力する（登録・修正・削除）。
- **ここでしないこと**：たくさんの消耗品をまとめて見ること（ステーションの在庫、装置とストッカーで見る）。
- **探し方**：ID の一部でも合えば、候補を ID の順に並べ、選んで開く（合わせ方はマップの一覧と同じ。大文字・小文字と「-」は気にしない）。ID がぴったり合うものがあれば、すぐに開く。開いた消耗品は URL の # のあと（`#/consumables/T-0101`）に覚える。
- **開いた消耗品**：ID、品種、新品・中古品、所在、加工の種類、予約、指名と、これまでの動き（新しい順）を出す。
- **指名（AGV での交換）**：「指名する」と「AGV で交換する」は、**1つの操作にまとめる**（domain.md の「AGV を使って受け渡す」は、届ける消耗品の指名として扱うため）。
  - 届ける装置を選んで指名する。指名できるのは、ステーションにある、要確認でない新品で、届ける予約も出庫の頼みもないもの。ほかは押せなくし、その理由を出す。
  - 指名してあれば「指名を取り消す」を出す。届ける搬送に AGV を割り当てたあとは、取り消せない。
  - 指名と取り消しは戻せる操作なので、確かめる画面は出さない。
- **在庫の手入力**（保守以上）
  - **登録**：ID、品種、新品・中古品、所在を、すべて空から入れ、全部を入れるまで保存できない。登録済みの ID は使えない。
  - **直す**：品種、新品・中古品、所在を変えられる（ID は変えられない）。入力欄には **いまの記録を入れておき**、記録にない項目（品種が不明、所在不明など）は未選択にする。何も変えていなければ保存できない。
  - 登録と直すときに選べる所在は、**ステーションと、装置のストッカーの空きスロット**（プレートに載せたまま置く装置は、ストッカー）。直すときは、いまの所在も選べる。
  - **消す** は、確かめる画面を出してから消す。
  - 直したり消したりできないのは、**AGV の中、加工部・受け渡し部にあるもの、AGV を割り当て済みの搬送の予約が付いているもの、出庫を頼んだもの**。割り当て前の予約や指名だけなら、直せる（直すと予約や指名を解き、不足と回収の判断をやり直す）。押せないときは、その理由を出す。

### 6 マップの編集

- **目的**：現場の床と同じマップを作り、**検証してから公開する**。
- **使う人**：管理者。
- **やること**
  - パネル（種類、つながり、距離、向き、充電ピン、キャリアの高さ、下ろす角度）を置いて直す。
  - 装置とステーションの外形を入れる。
  - 下書きを保存し、検証し、公開する。
- **ここでしないこと**：AGV を動かすこと、運転中の様子を見ること。
- **置くもの**：選ぶ、通常パネル、受け渡しパネル、待機パネル、特殊消耗品受け渡しパネル、つなぐ、消す。パネルは空いた格子にだけ置く。編集する格子は、パネルのまわりに1枚ずつ空けて広げる。
- **パネルの ID**：置いたときに、**種類ごとの頭文字（通常 P、受け渡し D、待機 SB、特殊 SP）に、まだ使っていないいちばん小さい番号** を付ける。あとで直せる（同じ ID は使えない）。装置やステーションの受け渡しパネルの ID は直せない。
- **つなぐ**：**上下左右に隣り合う2枚だけ** つなげる。**向きと距離は十字の位置から計算** して入れておき（整数に丸める）、**一方通行にはしない**。あとで実測に合わせて直せる。向きは、選んだパネルから見た向きで出して直す。受け渡し・待機パネルへのつながりは一方通行にできない。
- 種類を変えたときは、その種類に付けられない充電ピンと、キャリアを下ろす角度を外す。
- 消すと、そのパネルのつながりも消す。下書きを保存するまでは戻せる操作なので、確かめる画面は出さない。
- **装置とステーションの外形** は、その受け渡しパネルを選んだ欄で入れる（mm、左・上・幅・奥行き）。
- **キャリアの高さ**：公開中の版の受け渡しパネルごとに、**下書きとは別に「高さを保存する」で、すぐ使う**（1 以上の整数 mm。空にして保存すると設定なし＝AGV が測る）。AGV が測った値か手入力した値かと、保存した日時を出す。
- **下書きの保存と検証**：下書きは検証せずに保存できる。「確かめる（検証）」で、サーバーが下書きを確かめ、見つかった問題を出す。
- **公開**：検証で問題がなかった下書きで、**運転状態が停止、走っている AGV がないときだけ** 公開できる（確かめる画面を出す）。**公開したら、すぐにその版に切り替える**。押せないときは、その理由を出す。
- **保存していない変更があるまま、ほかの画面へ移るとき** は、確かめる画面を出す。ブラウザーを閉じる・読み込み直すときも、ブラウザーの確かめる画面を出す。

### 7 AGV と AGV の種類の登録

- **目的**：システムが動かす AGV と、その性能を **正しく登録する**。
- **使う人**：管理者。
- **やること**
  - AGV を加えて、AGV の種類とキャリアの種類を決める。
  - AGV の種類ごとに、速さ、充電に向かう残量と割り当てに戻す残量、特殊消耗品受け渡しパネルを走れるかを決める。
  - 起動したときの登録の食い違いを直す。
- **ここでしないこと**：コントロールステータスの切り替えなど、運転中の操作（マップの画面で行う）。
- **AGV の一覧**：登録が食い違っている AGV を上にし、それぞれの中と残りは番号の順（一覧の決まりと同じ）。
- **AGV を加える**：番号、AGV の種類、キャリアの種類をすべて入れる。使っている番号は使えない。加えた AGV は、**切り離しから始める**。
- **AGV を変える・消す**：AGV の種類とキャリアの種類を変えるのと、AGV を消すのは、**切り離しのときだけ**。ほかのときは押せなくし、その理由を出す。消すときは確かめる画面を出す。
- **登録の食い違い**（交通整理と配車の片方にしか登録されていない AGV）：「登録をそろえる」で、足りない側の項目（配車にないならキャリアの種類、走行にないなら AGV の種類）を入れて両方に登録する。そろえた AGV は切り離しから始める。いらない AGV なら消す（確かめる画面を出す）。
- **AGV の種類**
  - 前進・後退の速さ（mm/s）と回転の速さ（°/s）は **1 以上の整数** で、必ず入れる。
  - 充電に向かう残量と割り当てに戻す残量は **0〜100 の整数**。種類を加えるときだけ空にでき、空なら、そのときの既定値で埋めて保存する（domain.md）。割り当てに戻す残量は、充電に向かう残量以上。
  - 特殊消耗品受け渡しパネルを走れるかは、加えるときは「走れない」から始める（domain.md の、省略したときの扱い）。
  - 種類の値は **いつでも変えられる**（次の割り当てと充電の判断から効く）。種類を消せるのは、**使う AGV がないときだけ**（確かめる画面を出す）。
- 保存は戻せる操作なので、確かめる画面は出さない。管理者でなければ、どの操作も押せなくし、その理由を出す。

### 8 消耗品の構成

- **目的**：消耗品を扱うための **決まりごと**（加工の種類、品種、装置、ステーション）を登録する。
- **使う人**：管理者。
- **やること**
  - 加工の種類ごとに、運び方、キャリアの種類、キャリアに入る個数を決める。
  - 品種を登録する。
  - 装置（受け渡しパネル、ストッカーとスロットの数）、ステーションを登録する。
- **ここでしないこと**：ストッカーの設定（装置とストッカーで行う）。
- タブで、加工の種類、品種、装置、ステーションを切り替える。
- **名前（ID）**：加工の種類・品種・装置・ステーションの名前（ID）は、**登録したあとは変えられない**（ほかの記録から参照されるため）。変えたいときは、使われていなければ消して加え直す。同じ名前は使えない。
- **加工の種類**：名前、運び方（プレート搬送・専用 AGV 搬送）、キャリアの種類、キャリアに入る個数（1 以上の整数）をすべて入れる。
- **品種**：名前と加工の種類を入れる。加工の種類は、使われていないときだけ変えられる。
  - **ID と品種の対応** を、品種ごとに加える・外す。どの品種にもまだ対応させていない ID だけ加えられる。**在庫にある ID は外せない**。
- **装置**：ID、受け渡しパネル、**ストッカーごとのスロットの数**（1 以上の整数、ストッカーは1つ以上）を入れる。「プレートに載せたまま置く」装置は、スロットの数の代わりにストッカーの数を入れる。
  - ストッカーやスロットを減らすのは、**減るぶんが空のときだけ**。受け渡しパネルと置き方（スロットかプレートか）は、使われていないときだけ変えられる。
- **ステーション**：ID と受け渡しパネルを入れる。受け渡しパネルは、使われていないときだけ変えられる。
- **受け渡しパネルの選び方**：公開中のマップの受け渡しパネルと特殊消耗品受け渡しパネルのうち、**まだどの装置にもステーションにも使われていないもの**（パネル1枚に、装置かステーションは1つだけ）。直すときは、いまのパネルも選べる。
- **消せるのは、使われていないときだけ**（確かめる画面を出す）。加工の種類は、その加工の種類の品種がないとき。品種は、消耗品の記録とストッカーの設定で使っていないとき。装置とステーションは、中に消耗品がなく、かかわる搬送もないとき。押せないときは、その理由を出す。
- 名前や個数など、そのほかの値はいつでも変えられる。保存は戻せる操作なので、確かめる画面は出さない。管理者でなければ、どの操作も押せなくし、その理由を出す。

### 9 ユーザーとロールの管理

- **目的**：だれが、どの操作をできるかを **管理する**。
- **使う人**：管理者。
- **やること**
  - ユーザーを加える（デフォルトのロールを付ける）。ユーザーのロールを付け替える。
  - パスワードを忘れた人に、仮のパスワードを設定する。ログインの失敗でロックされた人のロックを外す。
  - ロールを加える・消す。ロールごとのパーミッションと、操作がないままログインしておける時間を決める。
  - デフォルトのロールを決める（管理者のロールは固定。デフォルトのロールは消せない）。
- **ここでしないこと**：自分のパスワードの変更（ログインしている人が、メニューの「パスワードを変える」から行う）。
- タブで、ユーザーとロールを切り替える。
- **ユーザー**
  - ロールの付け替えは、ロールの欄で選ぶ（戻せる操作なので、確かめる画面は出さない）。**最後の1人の管理者は、付け替えられない**（管理者がほかにもいれば、自分も含めて付け替えられる）。
  - **仮のパスワードは、システムが作り、その場で一度だけ見せる**（閉じたら、もう見られない）。「仮のパスワードにする」は、確かめる画面を出してから作る。ユーザーを加えるときも、加えたあとに仮のパスワードを見せる。どちらも、次のログインで変更を求める。
  - ユーザーを加えるときは、ユーザー ID を入れる（使っている ID は使えない）。デフォルトのロールを付ける。
  - ロックされた人には「ロックを外す」を出す。
- **ロール**
  - ロールを加えるときは、名前と、操作がないままログインしておける時間を入れる。加えたロールのパーミッションは、**「すべての画面を見る」だけ** から始める。
  - 時間は、**数（1 以上の整数）と単位（分・時間・日）** で入れる。加えるときの最初の値は 8時間。上限は設けない。
  - ロールの名前は、あとで変えられる（同じ名前は使えない）。
  - **管理者のロール** は、名前とパーミッションが固定で、消せない。**ログインしておける時間は変えられる**。
  - ユーザーに付けてあるロールは、**消せない**（先に付け替えてもらう）。デフォルトのロールも消せない。消すときは確かめる画面を出す。
  - ロールごとのパーミッションは、表のチェックで変えて、保存する。「すべての画面を見る」は、どのロールも外せない。
- 管理者のロールでなければ、どの操作も押せなくし、その理由を出す。
