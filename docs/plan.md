## DB（構成のデータの保存）

起動するときに DB から構成のデータを読み、実行中に変わる構成のデータ（ストッカーの設定、キャリアの高さ、コマンドの番号）を DB に書きます。

- 動いている間の状態（**消耗品の在庫と所在**、予約、搬送、AGV の位置など）の保存は、未決事項 #14（再起動したときの状態の復元）を決めてから行います。それまでは、再起動すると消えます。
- 画面がない間は、開発とデバッグ用の **初期データの JSON ファイル** を用意し、起動したときに DB が空なら、それを入れます。
- マップは、公開した版を **すべて番号を付けて残し**、起動したときは **一番新しい版** を使います。版を切り替えるタイミングは、マップの編集（backlog #5）に取りかかるときに決めます。

| 小ステップ | 内容 | 状態 |
|---|---|---|
| DB-1 土台 | EF Core、PostgreSQL と SQLite の切り替え、コンテキストごとの DbContext（スキーマ、または SQLite の別ファイル） | 済み |
| DB-2 マップ | 公開したマップの版、キャリアの高さ | 済み（PostgreSQL での統合テストは backlog #15） |
| DB-3 交通整理と配車 | AGV と AGV の種類（速さ、キャリアの種類、充電の設定値）、コマンドの番号 | 済み（PostgreSQL での統合テストは backlog #15） |
| DB-4 消耗品の管理 | 装置、ステーション、加工の種類、品種、ストッカーの設定、入庫の予定（ID と品種の対応） | 済み（PostgreSQL での統合テストは backlog #15） |

## FlowHub.Api での組み立て

各コンテキストのサービス、ポートの実装、購読（`Subscriptions.cs`）を組み立てて、動かせるようにします。画面向けの API（AGV の様子、ステータスの切り替え、マニュアルの操作など）は、画面に取りかかるときに作ります。

| 小ステップ | 内容 | 状態 |
|---|---|---|
| API-1 組み立て | 起動時に DB を開き、各コンテキストのサービスを作って、購読をつなぐ。イベントは処理のあとに届ける。AGV との通信の窓口を開く | 済み |
| API-2 初期データ | DB が空なら、開発用の初期データの JSON ファイル（マップ、AGV、消耗品の構成）を入れる。起動したら、不足と回収の判断を1回行う（SYS-1 で「スタートしたら1回」に変える） | 済み |
| API-3 ポートの仮の実装 | 装置・ステーション・上位システムとのやり取り（方式は未決事項 #11）を、下のシミュレーターで仮に実装する | 済み |

### 初期データ

- 設定（`InitialData:Path`）で **ファイルを指定したときだけ** 入れます。開発用の設定（appsettings.Development.json）にだけ書き、本番の設定には書きません。
- マップ、交通整理、配車、消耗品の管理の **4つの DB がすべて空のときだけ**、まとめて入れます。1つでも中身があれば、何も入れません（複数の DB にまたがる構成が、中途半端に入らないようにするため）。
- 入れる前に全体を確かめ、**ファイルがない、または中身が正しくないとき** は、何も入れずに、ログに出して **起動しません**。
- 中身は、動作を確かめやすい小さな構成にします（実際の配置がわかったら合わせます）。

```
              ST-1（ステーション）
               |
SB ─ P1 ─ P2 ─ P3 ─ P4 ─ SB2         SB, SB2：待機パネル（SB2 は充電ピンあり）
     |                   |
     P8 ─ P7 ─ P6 ─ P5
          |    |
        DEV-2 DEV-1（装置の受け渡し）
```

| 構成 | 中身 |
|---|---|
| マップ | 通常パネル8枚の環。パネルの間はすべて1000mm、両方向。行き止まりは、ステーションの受け渡し、装置の受け渡し2枚、待機パネル2枚（1枚は充電ピンあり） |
| AGV | 種類は1つ（前進 500mm/秒、後退 250mm/秒、回転 90度/秒、充電の設定値は既定値）。AGV-1 と AGV-2、キャリアの種類は `tool-carrier` |
| 消耗品の管理 | 加工の種類 `drill`（キャリアに4本）、品種 `DR-5` と `DR-8`。装置 DEV-1、DEV-2（ストッカー1つ、スロット10個）。ストッカーの設定は DEV-1 が `DR-5` 3本・`DR-8` 2本、DEV-2 が `DR-5` 2本。ステーション ST-1。入庫の予定はなし（在庫はシミュレーターの補充で入る） |

### シミュレーター（装置・ステーション・上位システム）

本物の通信ができるまで、装置・ステーション・上位システムのポートは、**自動で完了を返すシミュレーター**（`FlowHub.Simulator`）で仮に実装します。待ち時間は `TimeProvider` で測ります（テストでは早送りできます）。待ち時間の既定値は仮の値で、現場の目安がわかったら合わせます。

| 頼み | シミュレーターがすること | 待ち時間（設定値） |
|---|---|---|
| 装置への受け渡しの許可 | 待ち時間のあとに、受け渡しの完了を通知する。出し入れした消耗品の ID は、頼んだとおり | 既定 **10秒** |
| ステーションへの受け渡しの許可 | 同じ | 既定 **10秒**（装置とは別の設定値） |
| ステーションへの出庫の頼み | 待ち時間のあとに、ステーションから「出た」を通知する | 既定 **10秒**（受け渡しとは別の設定値） |
| 上位システムへの補充の頼み | 待ち時間のあとに、頼まれた数だけ **新品** の消耗品を新しい ID（`SIM-品種-連番`）で作り、入庫の予定に登録して、ステーションで読み取った通知を送る。入庫するステーションは設定で指定する（指定がなければ、ID の順で一番目） | 既定 **60秒** |
| 上位システムへの段取り替えのエラー | ログに残すだけ | － |

- いつも頼んだとおりに完了します。時間のばらつきや、エラー（照合のエラー、空きスロットがないなど）は起こしません。必要になったら足せる作りにします。
- AGV は、本物か、AGV 側の別のシミュレーターがつないでくる前提です（AGV のシミュレーターはまだありません）。

## システムの運転状態

起動しただけでは自動でコマンドを出さず、運転状態をスタートにしたら出すようにします。仕様は domain.md の「システムの運転状態」にあります。

| 小ステップ | 内容 | 状態 |
|---|---|---|
| SYS-1 運転状態 | 停止とスタートの持ち方と切り替え（HTTP の窓口、起動したらすぐスタートにする設定）。停止中は自動のコマンドを出さない。スタートしたら、不足と回収の判断、一時停止した搬送の続き、割り当て、充電を行う | 済み |
| SYS-2 停止したときの止め方 | 通路にいる AGV を待機パネルへ動かす（充電ピンのある待機パネルを優先、なければ一番近い待機パネル、それもなければ受け渡しパネル）。受け渡しの途中の AGV は、その場で待つ | 済み |
