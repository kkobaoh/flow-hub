# ドメイン仕様

flow-hub が扱うドメインの仕様です。未決事項は [open-issues.md](open-issues.md) にまとめています。

## 消耗品

- 消耗品は **1個ずつ ID で管理** します。
- 消耗品は、次の3段階で分類・識別します。

| 段階 | 説明 |
|---|---|
| 加工の種類 | 消耗品を大きく分ける区分。どんな加工をするかで決まります |
| 品種 | 同じ加工の種類の中での区分。品種が違うと、同じものは加工できません |
| 個体（ID） | 1個ずつの消耗品。品種が同じでも、ID が違えば別の個体です |

### 互換性

- **互換性は品種の中だけ** です。同じ品種であれば、どの ID の消耗品を送ってもかまいません。
- **品種の間に互換性はありません**。同じ加工の種類でも、ほかの品種で代わりにすることはできません。必要な品種がないときは、補充を待ちます（「消耗品の補充」の節を参照）。

### 新品と中古品

| 区分 | 説明 |
|---|---|
| 新品 | まだ使っていない消耗品。段取り替えなどで回収された未使用の消耗品も新品として扱います |
| 中古品 | 一度使った消耗品。**加工部に取り込まれた時点で中古品** とみなします |

- 中古品は、同じ品種・同じ ID であっても、もう一度使うには条件があります（条件の内容は未定です）。
- 中古品を再使用するかどうかは **未定** です。当面は **再使用しない** 前提で設計します。
- ただし、将来再使用する可能性があります。再使用（中古品の管理）を後から加えられる設計にしておきます。
- ストッカーにある消耗品が新品か中古品かは、装置からは確かめられません。システムがこれまで記録してきたデータを正として扱います。中古品を新品と取り違えて装置に投入した場合は、装置側でエラーになります。

## 消耗品の搬送方式

加工の種類によって、次の2つの搬送方式のどちらかで運びます。どちらになるかは **加工の種類で決まります**。

| 搬送方式 | 対象の加工の種類 | 使う AGV | 加工の種類ごとに専用のもの |
|---|---|---|---|
| プレート搬送 | プレートに載せられるもの | ワーク搬送と兼用の AGV | プレート |
| 専用 AGV 搬送 | プレートに載らないもの | 消耗品搬送専用 AGV | キャリア |

- 1回の搬送でまとめて運べるのは、**同じ加工の種類の消耗品だけ** です。

### キャリア

- キャリアは、**AGV についている運搬用の箱** です。
- キャリアに何を入れるかは、キャリアの大きさで決まります。**プレートを入れる** ものと、**ワークや消耗品をそのまま入れる** ものがあります。
  - 兼用 AGV のキャリアには、プレートを入れます。
  - 消耗品搬送専用 AGV のキャリアには、消耗品をそのまま入れます。
- キャリアは **AGV に固定** です（付け替えはできません）。

### ワーク搬送と兼用の AGV

- ワークを運ぶ AGV として、すでに開発済みのものです。
- キャリアに **プレート** を入れて、消耗品を運びます。キャリアに入るプレートは **1枚** です。
- 兼用 AGV に **消耗品の搬送を割り当てるのは、このシステム** です。
- **ワーク搬送の配車** は、今回は考えません（このシステムの対象外とします）。

#### ワーク搬送との共存

- 今回の対象では、AGV が **ワーク搬送と共存することはありません**。
- 将来共存する場合も、**AGV の制御はこのシステムで行います**。共存するときの AGV の空き状況の把握や、走行の干渉の制御は、そのときに検討します。

### プレート

- プレートは、ワークと同じ形をした板で、消耗品をいくつかセットできます。
- プレートは **加工の種類ごとに専用** です。1枚のプレートに、違う加工の種類の消耗品は混ぜられません。同じ加工の種類であれば、品種の違う消耗品は一緒に載せられます。
- プレートは **載せ降ろしできます**。消耗品がいくつか載ったプレートは、プレートごとまとめて載せ降ろしします。装置にも、プレートごとそのまま載せ降ろしします。
- システムは、**プレートそのものの所在** と、**プレートに何が載っているか** を管理します。
- 装置の中でのプレートの扱いは、**装置によって異なります**。
  - プレートに載ったまま、ストッカーや受け渡し部に置かれる装置があります（この装置のストッカーにはスロットがありません。「装置のストッカー」の節を参照）。
  - ストッカーで消耗品だけが取り出され、**空のプレートが返ってくる** 装置もあります。
- **空のプレート** は、ステーションに置かれます。

### 消耗品搬送専用 AGV

- プレートに載らない加工の種類の消耗品を運びます。
- キャリアは加工の種類ごとに専用です。キャリアに入る消耗品の個数も、加工の種類で決まります（1個だけのものも、複数個入るものもあります）。

## ステーション

- ステーションは、**システムの中と外をつなぐ、消耗品の出入り口** です。消耗品はステーションに直接入庫・出庫されます。
- ステーションは、消耗品を **ストックし、その在庫を管理** します。ストックした中から、必要な消耗品を必要な装置へ運ぶ役割を持ちます。
- ステーションには、空のプレートも、消耗品が載ったプレートも置きます。
- ステーションは、入ってきた消耗品の **ID を読み取れます**。
  - 品種は読み取れないので、上位システムか人が、**前もって ID と品種の対応を登録** しておきます。ステーションで読み取った ID が、その対応にあれば、その品種の新品として入庫します。
  - 対応に **ない未登録の ID** は、品種のわからない消耗品として登録し、**要確認** にします。
  - 読み取った ID が、記録上 **所在不明** だったら、所在をステーションに確定させます。ただし、記録（品種など）が正しいとは限らないので、**要確認** にします（人が確かめるまで、届ける候補にしません）。
  - 読み取った ID が、記録上 **ほかの場所**（装置のストッカー、AGV の中など）にあることになっていたら、**通知を正として** ステーションにあるものとし、食い違いをログに残して画面で警告します。付いていた予約は解きます。
- 要確認の消耗品は、人がステーションで確かめて、**品種と、新品か中古品か** を直し、要確認を外せます。加工の種類は、品種から決まります。
- ステーションの **スペースの数（満杯）** は、ステーションの仕様が決まるまで扱いません。
- 1つのシステムに **ステーションが複数ある** ことがあります。
- 同じ品種が複数のステーションにあるとき、どれから持っていくかは **ルールとして設定で決められる** ようにします（例：装置から近い順、古いものから先に使う）。
- ステーションのストックは、**置けるスペースの数** で表します。1スペースに置くのは、消耗品1個のこともあれば、プレート1枚のこともあります。
- **入出庫口** は、独立した概念ではなく、**スペースが1つのステーション** として扱います。
- システムは、消耗品が **どのステーションにあるか** までを管理します。ステーションの中のどのスペースにあるかは、ステーションの仕様が決まるまで管理しません。
- 回収した消耗品を返すステーションは、**ステーションの選び方のルール** で決めます（今はステーションが1台）。
- ステーションは **開発中で、仕様は決まっていません**。次の点は未定です。
  - 消耗品の種類（加工の種類・品種）によって、ステーションの種類が変わるかどうか
  - 消耗品をプレートに載せたまま管理するか、プレートから外して1個ずつ管理するか
- このため、ステーションまわりは仕様が変わりやすい前提で、ほかの部分と切り離して差し替えられる設計にしておきます。

## 装置のストッカー

- 装置には **ストッカーがいくつかあります**。1台の装置にあるストッカーの数は、装置によって異なります。
- 1つのストッカーには **スロット** があり、スロットの数も装置によって異なります。1スロットに置ける消耗品は1個です。
  - 例：ストッカーが2つ、スロットが3つずつの装置なら、合計6スロットで、最大6個の消耗品をストックできます。
- プレートに載ったまま置く装置のストッカーには、**スロットがありません**。
- ストッカーに **どの品種を何個ストックしておくか** は、**システム側の設定** で決めます。
  - 設定するのは **ユーザー（顧客）** で、設定の内容は顧客の責任です。システムが設定を書き換えることはありません。
  - 同じ品種を複数のスロットに割り当てられます（例：品種 A を3個ストックする設定）。
  - スロットのない装置でも、設定は **プレートに載った消耗品の個数** で数えます。
- スロットは品種ごとに固定されていません。どの品種でも、空いているスロットに入れられます。
- 届けた消耗品を **どのスロットに入れるかは、システムが指示** します。
  - 指示するのは、**空いているスロットのうち、番号が一番小さいもの** です。番号は、**ストッカーの番号の順、同じストッカーの中ではスロットの番号の順** に比べます。
  - 指示は、装置で降ろすときの **搬送の許可に、消耗品の ID ごとの入れ先のスロットを入れて** 渡します。
  - 空いているスロットが、降ろす消耗品の数より **足りないとき** は、許可を出さずにエラーにし、画面で知らせます（搬送は受け渡し待ちのまま止まります）。ユーザーに確かめてもらいます。
- 装置から回収するときは、搬送の許可に、**取り出すスロット** を入れて渡します。
  - 回収する消耗品が、記録上 **ストッカーにないとき** は、許可を出さずにエラーにし、画面で知らせます。ユーザーに確かめてもらいます。

- システムは、ストッカーにある消耗品の所在を、**装置・ストッカー・スロット** の単位で管理します。

### 加工の種類ごとの設定

- 消耗品の管理は、**加工の種類ごとに、キャリアの種類と、キャリアに入る消耗品の個数** を設定として持ちます。
- 搬送計画は、この設定を使って、1往復でまとめて運ぶ単位を決めます。

### 不足の判断

- 不足は、ストッカーごとではなく **装置全体** で数えます。装置のすべてのストッカーにある、ある品種の新品の個数が、設定を **1個でも下回ったら** 不足とみなします。
- **中古品は在庫として数えません**（当面の扱いです）。
- その装置へ **届ける途中の新品**（AGV に積んでいるもの、受け渡し部にあるものなど）も、個数に数えます。数えないと、同じ不足に対して何度も搬送を頼んでしまうためです。
  - 搬送の途中で AGV がエラーになったなど、届けられなかった場合の扱いは、あとで検討します（未決事項「異常時の扱い」）。

### 届けるときの選び方

- ステーションから届ける消耗品は、同じ品種の中では **先に入ったもの（古いもの）から** 選びます（先入れ先出し）。何をもって「古い」とするか（ステーションに **入庫した日時** か、消耗品が **出荷された日時** か）は未定です（未決事項）。
  - 決まるまでは、仮に **ステーションに入庫した順** で選びます（確認待ち）。
- ステーションに、必要な数の **一部しかない** ときは、**あるぶんを先に届け**、残りは補充を頼んで待ちます。
  - 補充の頼みは、上位システムとのやり取りのポートを通して出します。
  - 品種ごとに、**補充を頼んで、まだ入庫されていない数** を覚えておきます。頼む数は「足りない数 − まだ入庫されていない数」とし、**1以上のときだけ** 頼みます（同じ不足に二重に頼まず、待っている間に不足が増えたら、増えたぶんだけ頼むため）。
  - その品種の新品が、ステーションで ID を読み取って入庫されたら、まだ入庫されていない数を1つ減らします。
  - 要確認の消耗品を人が直したときは、**未登録の ID として入ってきた消耗品** を直したときだけ、入庫に数えます（品種の対応の登録が漏れたまま届いた補充とみなします）。照合のエラーで回収したものや、所在不明から見つかったものなど、**前から登録されていた消耗品** を直しても、入庫に数えません。
    - 未登録の ID として入ってきた消耗品でも、**中古品** と直したときは、入庫に数えません（補充で届くのは新品のため）。
  - 一度頼んだ補充の数は、あとから減らせません。このため、頼んだあとに要確認の消耗品を直して使ったときなどは、必要より多く補充されることがあります。多すぎたぶんは、ステーションの在庫として次に使います。
- ステーションの選び方のルールが決まるまでは、**登録されている唯一のステーション** を使います。ステーションが **2台以上** あるときは、エラーにします。

### 判断のやり直し

- 不足と回収の判断は、**その装置にかかわる変化があるたびに、すぐやり直します**。定期的なやり直しはしません。
  - 変化とは、ストッカーの設定の変更、受け渡しの完了、ステーションへの入庫、廃棄リクエストなどです。
- やり直した結果、すでに頼んだ搬送の要求が要らなくなったときは、**割り当て前のものは取りやめます**。割り当てたあとのものは、そのまま運びます。
  - やり直すたびに、**割り当て前の要求はすべていったん取りやめて出し直します**。必要時刻は保ちますが、配車の待ち行列の「同じ必要時刻なら頼まれた順」は、出し直した順になります。
- ストッカーの設定を **まだしていない装置** は、不足も回収もないものとします（設定にない品種として、全部を回収することはしません）。
- 廃棄リクエストは、**その装置のストッカーにある消耗品** のものだけを受け付けます。それ以外はエラーにします。
- 搬送が中断（異常）したときは、未決事項「異常時の扱い」が決まるまで、その消耗品を **届ける途中の数に入れたまま** にします。

### 回収の判断

- **設定にない品種の新品** は、自動で回収します。
- **中古品** は、自動では回収しません。中古品になったときに装置から届く **廃棄リクエスト** で回収します。回収のきっかけを1つにそろえ、同じ消耗品の回収が2重に動かないようにするためです。
  - 廃棄リクエストは、使い終わった中古品が **ストッカーに戻ったあと** に届きます。
- **設定より多くある品種** は、そのせいで **ほかの品種の不足を補えない（空きスロットが足りない）ときだけ** 回収します。
  - 回収するのは、足りない空きの数だけです。
  - どの個体を回収するかは、**品種の ID の順、同じ品種の中では消耗品の ID の順** で選びます。
- 空きスロットの数は、次のように数えます。
  - 空き ＝ 容量 −（ストッカーにある数 − 設定にない品種の回収で空く数 ＋ 届ける途中の数）
  - **中古品** も、スロットをふさぐものとして数えます。
  - **届ける途中の消耗品** も、スロットをふさぐものとして数えます。
- すでに回収を頼んだ消耗品は、もう一度回収を頼みません。また、**不足の数にも空きの数にも入れません**（もうすぐなくなるものとして扱います）。
- 上の空きの式は、**設定より多い品種を回収するかどうか** の判断にだけ使います。

### 届ける数の上限

- 届ける要求は、**今、実際に空いているスロットの数から、届ける途中の数を引いた数** までしか出しません。
  - 回収を頼んだだけで、まだ取り出していない消耗品は、スロットをふさぐものとして数えます。

### 搬送の要求のまとめ方

- 1往復でまとめるのは、**同じ装置・同じ加工の種類** のものを、**キャリアに入る個数まで** です。
- **届けるものと回収するものは、別々の往復** にします（1回の訪問では、どちらか一方しかできないため）。
- 不足の合計がキャリアに入る個数より多いときは、**不足を見つけた時刻の順、同じなら品種の ID の順** に積みます。
  - 複数の装置で、不足を見つけた時刻も品種も同じときは、**装置の ID の順** にステーションの在庫を割り当てます。
- 回収するものは、**不整合、設定にない品種、設定より多い品種、廃棄リクエストの順** に積みます。同じ理由の中では、**品種の ID の順、同じ品種の中では消耗品の ID の順** です。
- 必要時刻が同じときは、**届ける要求を回収の要求より先に** 頼みます。
- 中古品は、装置からの **廃棄リクエスト** を受けて回収します。

### 必要時刻

- 届ける要求の必要時刻は、**不足を見つけた時刻** です（未決事項「届ける順番の優先順位」が決まるまで）。
  - 不足が続いている間は、**最初に不足を見つけた時刻を保ちます**（やり直すたびに新しくすると、後回しになり続けるため）。
- 回収の要求の必要時刻は、**回収が必要だと判断した時刻**（廃棄リクエストなら、それを受けた時刻）です。届ける要求と同じ尺度で並べます。
- 1往復に複数のものをまとめたときは、**一番早い時刻** を、その要求の必要時刻にします。

## 配車のきっかけ

システムは、次のきっかけで AGV に消耗品の搬送を割り当てます。

| きっかけ | 判断する者 | 搬送の内容 |
|---|---|---|
| ストッカーの品種の不足 | システム（設定と在庫の比較） | 不足した品種の消耗品をステーションから装置へ届ける |
| 設定にない消耗品がストッカーにある | システム（設定と在庫の比較） | 設定にない消耗品を装置からステーションへ回収する |
| 消耗品の廃棄リクエスト | 装置 | 使い終わった消耗品を装置からステーションへ回収する |

- 同じ装置へ運ぶものが複数あるときは、同じ加工の種類の範囲で **まとめて運びます**。
  - まとめるのは **消耗品の搬送計画** の役割です。キャリアに何個入るかは加工の種類で決まり、それを知っているのが消耗品の側だからです。配車は、**1つの搬送の要求を1往復** として扱い、運ぶものを知りません。
  - ストッカーに空きがないときは、消耗品の搬送計画が、**空きの数までしか届ける要求を出さず**、残りは回収が終わってから出します。
  - まとめるのは、**その時点である要求だけ** です。ほかの要求を待たずに、すぐ出発します。搬送が多すぎるようなら、少し待ってまとめる時間を設定で持てるようにすることを、運用を見て検討します。
- ストッカーに空きがないときは、**回収が終わるのを待ってから** 新しい消耗品を届けます。
- 受け渡し部では、**1回の訪問で、届けるか回収するかのどちらか一方しかできません**。同じ訪問で両方を行うことはありません。
- 消耗品は、**加工で先に必要になりそうな順に届ける** よう、優先順位を制御します。優先順位のロジックの詳細は、あとで詰めます。

### 責務の範囲外

- 廃棄リクエストが来ないために回収が始まらず、ストッカーに空きができないまま届ける搬送が待ち続けることがあります。この詰まりを解消するのは **装置や運用の責務** で、本システムの責務ではありません。システムは中古品を自動で回収しません。

## AGV の走行

- AGV は **ライントレース** で走行し、**パネルとパネルの間** を走ります。
- 1枚のパネルには、**十字のライン** が引いてあります。
- AGV は十字を検出すると、自分がパネルの上にいることを知り、**システムに通知** します（この通知は、前進・後退の **完了の通知** と同じものです。「AGV からの完了の通知」の節を参照）。

### パネルとマップ

- パネルは、**装置の設置状況に合わせて** 設置します。
- パネルは **格子状に、すき間なく** 並んでいます。
- パネルは基本的に **正方形で、十字のライン** が引かれています。調整が必要な場所ではラインを引き直すため、**十字と十字の間隔は等間隔になりません**。
  - このため、マップには **隣り合うパネルの十字の間の距離** を、パネルの組ごとに持ちます。
- コースによっては、**ラインが斜めに引かれる** ことがあります。斜めでないと成り立たないコースがあるためです。
  - このため、マップには、パネルとパネルの間を進むときの **向きを絶対角度で** 持ちます（0度・90度・180度・270度に限りません）。
- 十字と十字の間のラインは、斜めのものも含めて **まっすぐ** です（途中で曲がるラインは、基本的にありません）。このため、逆向きに進むときの向きは、**ちょうど 180度反対** になります。また、前進や後退で移動しても、AGV の向きは変わりません。
- ラインを引き直すときは、**AGV が隣り合うパネルにそれぞれ停車しても、ぶつからないこと** を条件にしています。
- 隣り合う2枚のパネルの間に引くラインは **1本だけ** です。同じ2枚のパネルのつながりを二重に登録することはできません（向きが逆でも同じつながりとみなします）。
- マップは **離れ島**（ほかとつながっていないパネルの集まり）があってもかまいません。島をまたぐ経路はないものとして扱います。
  - ただし、**それぞれの島の中では、一方通行の向きも守ったうえで、どのパネルからどのパネルへも行ける** ようにします（入れるのに出られない区画を作らないため）。これは **常に検証** します。
  - 検証は、マップを公開する（スナップショットにする）ときに行います。編集の途中の下書きは検証しません（ラインを引いている途中は、一時的に行き来できない区画ができるため）。
  - 離れ島を許さない現場向けに、**すべてのパネルが1つにつながっていることを検証するオプション** を用意します（既定はオフ）。
- 公開したマップの版は、**すべて番号を付けて残します**。起動したときは **一番新しい版** を使います。版を切り替えるタイミングは、マップの編集に取りかかるときに決めます。
- ステーション、装置の受け渡し部、充電ポートは、それぞれ **特定のパネルの上** にあります。

### パネルの種類

| 種類 | 役割 | 入り方 | 出方 | 回転 | 充電ピン |
|---|---|---|---|---|---|
| 通常パネル | 十字のラインがある、走行用のパネル | 制限なし | 制限なし | できる | 設置できない |
| 受け渡しパネル | 装置やステーションと AGV の間で、ものを受け渡す | **前進でのみ** | **後退でのみ** | **できない** | 設置できる |
| 待機パネル | 待避するためのパネル | **前進でのみ** | **後退でのみ** | **できない** | 設置できる |

- 受け渡しパネルと待機パネルは **行き止まり** です。隣り合う通常パネルは1枚だけで、出入り口は1か所だけです。このため、そこに止まっている AGV は、**ほかの AGV の通行をふさぎません**。
  - 前進で入り、後退で出るため、受け渡しパネルと待機パネルへのつながりは **一方通行にできません**。
- 受け渡しパネルと待機パネルには、**充電ピン** を設置できます。充電ピンのあるパネルに **停車している間は充電** できます。
  - 現場の設置状況によって、受け渡しパネルや待機パネルでも充電ピンがないことがあります。**充電ピンを設置しているかどうかは、パネルごとにマップの情報として持ちます**（既定は「設置していない」）。
  - 充電ピンの有無は、めったに変わらないので、マップの **版の中**（スナップショット）で管理します。
  - 「充電ポート」は独立した設備ではなく、**充電ピンを設置した受け渡しパネルか待機パネル** のことです。
- 受け渡しパネルと待機パネルには前進でしか入れず、中では回転できません。このため、AGV は **入る前に、隣のパネルで向きを合わせておく** 必要があります。経路を求めるときは、パネルだけでなく **AGV の向き** も含めて考えます。

### 経路の求め方

- その場で回転するとき、向く先の候補は、**そのパネルのラインの向き**、**その逆向き**、**指定されたゴールの向き** だけにします（それ以外の角度に向いても、その先へ進めないため）。
- ゴールに着いたときの向きは、**指定することも、指定しない（どの向きでもよい）こともできます**。行き止まりのパネルは前進でしか入れないので、入る向きは、つながりの向きで自然に決まります。
- 一方通行のつながりは、**後退でも逆向きには通れません**。一方通行の向きは、AGV の向いている方向ではなく、**実際に動く方向** で決まります（後退での逆走を許すと、向かい合いを起こさないという一方通行の目的が崩れるため）。

### 位置の推定

- AGV は、**自分でマップを持たず、パネルを見分けることもできません**。システムから送られる走行の指示に従って動きます。
- 前進・後退の指示には、**動作ごとに、どのパネルへ移動するか** の情報が入っています。AGV は、この情報と、十字の検出（行き止まりのパネルでは到着の判断）から、**今いるパネルを推測** します。
- システムは、AGV からの **完了の通知**（着いたパネルの ID、回転後の絶対角度）で、AGV の位置と向きを把握します。
- **最初の位置** は、ユーザーがシステムに登録して決めます。システムは **位置リセット** のコマンドで、AGV にパネルと絶対角度を教えます。
- 十字の **検出漏れや誤検出** が起きたときは、AGV がエラーを発報し、**ユーザーが手で修正** します。

### 受け渡しの手順

- AGV は **装置の上を走ります**。装置の上にパネルを敷き、その上を走ります。
- 受け渡し部では、AGV が **キャリアを下に下げて**、装置（またはステーション）とものを受け渡します。
- 装置やステーションとのやり取り（搬送の許可を出す、受け渡しの完了を受ける）は、**消耗品の管理** が受け持ちます。配車は、搬送の許可がほしいことをイベントで知らせ、消耗品の管理が装置やステーションに許可を出します。受け渡しの完了は、消耗品の管理が配車に伝えます。
  - ワーク搬送と両立するときは、同じ装置との受け渡しを、消耗品とワークで取り合うことになります。そのときに **装置とのやり取りを別のコンテキストに切り出せる** よう、受け渡しのやり取りは、消耗品のモデルに依存しない形で分けておきます（未決事項「消耗品とワークの両立」）。
- 受け渡しの手順は、次のとおりです。
  1. システムが AGV に **キャリアを下げるコマンド** を送ります。
  2. AGV は、キャリアが下がったことを検出したら、**完了の通知** を送ります。
  3. システムは、その通知をもとに、装置（またはステーション）に **搬送の許可** を出します。
  4. 装置（またはステーション）が、ものをキャリアに出し入れします。
  5. 装置（またはステーション）から **完了の通知** が来たら、システムは AGV に **キャリアを上げるコマンド** を送ります。
  6. AGV は、キャリアが上がったら **完了の通知** を送ります。これで受け渡しの完了です。
- 装置（またはステーション）からの受け渡しの完了の通知には、**出し入れした消耗品の ID** が入ります。
  - 通知の ID が、頼んだものと違ったら、**通知の ID を正として所在を更新** し、食い違いをログに残して画面で警告します。どちらが正しいかは、ユーザーに確かめてもらいます。
- **届けるときと回収するときで、手順は同じ** です。ものの向き（キャリアから装置へ、装置からキャリアへ）が逆になるだけです。
- **キャリアを下げるコマンド** と **キャリアを上げるコマンド** は、緊急停止・アラームクリアと並ぶ **独立したコマンド** です（動作コマンドの配列には入りません）。番号も同じように付けます。
- キャリアを下げるコマンドには、**下げる高さ** を入れて渡します。
- キャリアを下げている間に緊急停止やエラーが起きても、**ユーザーはキャリアを上げられません**。アラームクリアをしてから、**システムからキャリアを上げるコマンド** を送って上げます。
- キャリアを下げる動作は、**受け渡しパネルの上でしか** できません。
  - システムがキャリアを下げるコマンドを出せるのは、AGV が **受け渡しパネルにいて、走行しておらず（待機中）、キャリアが上がっているとき** だけです。それ以外で頼まれたら受け付けません。AGV がそれ以外のときに下げるコマンドを受け取ったら、AGV がアラームを通知します。
- キャリアを下げている間は、**走行できません**。システムは、キャリアが上がるまで AGV を走らせません。
- キャリアの「下がった」「上がった」「測定した高さ」の通知も、ほかの通知と同じく **コマンドの番号で見分けます**。予期しないときに届いたら、**無視して、ログに残し、画面で警告** します。
- 緊急停止のときは、まだ渡していない **キャリアのコマンドも取り下げます**（止まっている間にキャリアが動き出さないようにするため）。
- キャリアを上げ下げしている最中にエラーが起きたら、AGV は **その場で止まります**。**アラームクリアで、途中から再開** できます。
- 位置リセットをしても、システムは **キャリアの状態を保ちます**（キャリアが下がっていれば、下がったまま）。
- キャリアを上げるコマンドを出せるのは、**キャリアが下がっているとき** です（緊急停止中は、先にアラームクリアが要ります）。
  - **「異常」のとき** は、アラームクリアはできないので、**位置リセットのあとに** 上げます。位置リセットを受けた AGV は自分でアラームをクリアし、キャリアの状態は保たれるので、そのあと上げられます。
- 緊急停止やエラーで取り下げたキャリアのコマンドは、走行の区間と同じく、**アラームクリアの完了の通知を受けたあとに、新しい番号で渡し直します**。
- キャリアがすでに下がっているときに、もう一度下げるように頼まれたら、受け付けません。
- キャリアを下げる **高さは、受け渡し部ごとに決まって** います。
  - 高さは、**マップの情報**（受け渡しパネルの情報）として持ちます。
  - 現場で設置するときに決めます。現場で編集することもあります。
  - AGV が **自動で測定して**、高さを設定することもあります。測定した高さは AGV から通知され、システムが保存します。
  - 現場での手入力と AGV の自動測定の両方があるときは、**新しく設定されたほう** を使います。
  - キャリアを下げるコマンドに入れる高さは、**交通整理がマップの設定から読みます**。
  - **高さが設定されていない** 受け渡しパネルでは、**AGV が自動で測定** します。キャリアを下げるコマンドに **高さを入れずに渡す** と、AGV が測定します。
    1. AGV が測定して、**測定した高さを通知** します。
    2. システムが、その高さをマップの設定に保存します。
    3. AGV が、キャリアが下がったことを **完了の通知** で知らせます。
    4. そのまま受け渡しを続けます。
  - 高さは、マップのスナップショット（版で管理するパネルとつながり）とは **別の、受け渡しパネルごとの設定** として持ちます。たびたび変わる値で、経路探索や予約には関係しないため、版で縛らず、変わったらその場で新しい値を使います。

### 動き方と走行の指示

- AGV ができる動きは、**その場での回転**、**前進**、**後退** だけです（走りながら曲がることはできません）。
- 通常パネルの上でも **後退で走れます**。ただし、**後退の速度は前進より遅い** です。
- 回転は **1度単位** です。システムは回転後の **絶対角度** を送り、どちら回りに回るかは **AGV が判断** します。AGV は必ず **近い回り** で回転します（斜めのラインに合わせるため、1度単位になっています）。
- AGV に出した走行の指示は、**あとからキャンセルできません**。
- このため、システムはゴールまでの指示を一度に出さず、**ある区間ぶんの指示を、小分けにして順に出します**。
- 区間ぶんの指示をまとめて出すことで、AGV がパネルごとに **停止・再加速せずに** 走れます。
- **区間は、回転で区切ります**。1つの区間は、まっすぐ進む動作の並びと、最後の回転からなります。
  - 前進と後退は別の指示なので、**前進と後退が切り替わるところでも区切ります**（回転なしで切り替わることは、今の経路探索ではまず起きません）。
  - ゴールに着く最後の区間は、**回転で終わらないこと** もあります。
- 指示は、**動作の並び** で出します。
  - 例：「800mm 前進（パネル B へ）、800mm 前進（パネル C へ）、絶対角度 90度へ回転」
  - 前進の1つ1つは、**次の十字のラインまで** の距離と、**移動先のパネル** です。この例では、800mm 進んだ地点（パネル B）と、さらに 800mm 進んだ地点（パネル C）に十字のラインがあります。
  - 後退も、前進と同じ形式で指示します（例：「800mm 後退（パネル A へ）」）。
- 次の区間の指示は、**AGV が回転を終えたあと** に出します。

### AGV との通信（コマンドの受け渡し）

- AGV は、システム（サーバー）に対して **常に GET のリクエストを送り、コマンドを取りに来ます**（ロングポーリング）。
  - 渡すコマンドがあれば、**コマンドができたタイミングで、すぐにレスポンスを返します**。
  - 渡すコマンドがなければ、**25秒待って、コマンドがなかったことを返します**。
  - AGV は、レスポンスを受け取ったら、また GET のリクエストを送ります。
- **緊急停止なども同じ方法** で渡します。システムから AGV へ直接送る経路はありません。
- このため、本書で「システムから AGV へ送る」と書いているものは、実際には「**AGV が次に取りに来たときに渡す**（取りに来ている最中なら、すぐに渡す）」ことを指します。
- **1回のレスポンスで、複数のコマンドを渡せます**（区間ぶんの指示をまとめて渡せます）。
- AGV からシステムへの **完了の通知** と **エラーの通知** は、GET とは **別のリクエスト（POST）** で送られてきます。
- **通信が切れたとき、AGV は自分で止まります。**
  - **3分くらい** 通信できないと止まります。
  - 止まった AGV は **アラームを発報** しているので、通信が戻ったあとに **アラームクリアが必要** です。
  - システムは、通信が切れている間は AGV が止まったことを知れません。**通信が戻ったときに、エラーとして通知** されます。
- AGV には **バンパースイッチ** があり、ぶつかったときに止まれます。ただし、これはぶつかったあとに止まる最後の守りです。ぶつからないようにするのは、これまでどおりパネルの予約で行います。

### AGV からの完了の通知

- AGV は、**動作（回転、前進、後退）を1つ終えるごとに、完了を通知** します。
  - **回転** の完了：回転を終えたあとの **今の絶対角度** を返します。
  - **前進・後退** の完了：着いた **今のパネルの ID** を返します。
- 受け渡しパネルと待機パネルには十字のラインがありませんが、AGV は **到着したことを自分で判断できる** ので、到着したときに完了を通知します。
- コマンドごとの完了の通知は、次のとおりです。

| コマンド | 完了の通知 |
|---|---|
| 動作コマンド | **受信の完了** の通知がある。配列をすべて終えたときの完了の通知は **ない**（最後の動作の完了の通知で、終わったとわかる） |
| 前進・後退 | あり（動作の種類と、着いた（と AGV が推測した）パネルの ID） |
| 回転 | あり（動作の種類と、回転後の絶対角度。実際には誤差がある） |
| アラームクリア | あり |
| 位置リセット | あり |
| 緊急停止 | **なし。** かわりに、AGV が **アラームを発報** し、エラー「**サーバー要求エラー停止**」を POST で通知する |

- 回転の角度の誤差は、**AGV の制御の責務** です。システムは誤差を気にしません。回転の完了を受けたら、AGV の向きは **指示した角度** とします。
- AGV は、**再起動すると、内部に持っている指示と、今の位置を忘れます**（指示の番号も忘れます。下を参照）。
  - 再起動した AGV は、システムに **位置を取得するリクエスト** を送ってきます。システムは、**最後に把握していた位置をそのまま返します**。
  - AGV の再起動は、**ユーザーが行う** ことが前提です。再起動したら、ユーザーが AGV を手で **十字の上まで動かして、位置リセット** します。
  - 走行の途中で再起動しても、残っていた **予約は解放しません**。システムが「再起動した」と勘違いしているだけで、実際には AGV が走っていた場合に、ぶつかるおそれがあるためです。予約は、位置リセットで解放します。

### AGV のエラー

- AGV がエラーを出したときは、**AGV は止まり**、エラーを **POST で通知** します。
- エラーの種類は、次のとおりです。
  - 十字の検出漏れ
  - 十字の誤検出
  - バンパースイッチが押された
  - 通信が切れた（通信が戻ったときに通知される）
  - 充電切れ
  - モーターのドライバーのエラー
  - ハードウェアのエラー
  - サーバー要求エラー停止（システムが緊急停止を送ったとき）
- エラーの種類によって、システムの扱いを分けます。

| 分類 | エラー | システムの扱い |
|---|---|---|
| 位置がずれた可能性がある | 十字の検出漏れ、十字の誤検出 | 「異常」にする。位置リセットを待つ |
| 位置はずれていない | バンパースイッチ、通信が切れた、充電切れ、モーターのドライバーのエラー、ハードウェアのエラー、サーバー要求エラー停止 | 「緊急停止中」と同じにする。アラームクリアで続きを走れる（充電切れやハードウェアのエラーなどは、ユーザーが直してからアラームクリアする） |

- すでに「異常」のときに、位置はずれていない種類のエラーが届いても、**「異常」のまま** にします（「緊急停止中」にすると、アラームクリアで走り出せてしまうため）。
- 位置がわからない（まだ位置リセットしていない）AGV からエラーの通知が届いたら、**ログに残すだけ** にします。

- パネルとパネルの間で止まった AGV の位置リセットは、**ユーザーが AGV を手で十字の上まで動かしてから** 行います。将来は、自動で復旧することも考えます。

### 指示の番号

- AGV へ送るコマンドは、次の4つで、どれも **同じ立ち位置** です。
  - **動作コマンド**：1つの区間ぶんの、前進・後退・回転の組み合わせの **配列** を持ちます。
  - **緊急停止**
  - **アラームクリア**
  - **位置リセット**
- システムは、**コマンドごとに番号** を付けます。前進・後退・回転の1つ1つには番号を付けず、それらをまとめた **動作コマンドに1つ** の番号を付けます。AGV は、通知にそのコマンドの番号を入れて返します。
  - 番号は **1つずつ増やして** 付けます。番号の大小で、指示の順番がわかるようにするためです。
  - 番号は **AGV ごと** に数えます。
  - システムを再起動しても、位置リセットをしても、番号は **1 に戻さず、続きから** 数えます（そのため、システムは番号を保存しておきます）。古い指示への通知と見分けるためです。
  - **AGV は、再起動すると、指示の番号を忘れます。** AGV は、コマンドを取得するリクエスト（GET）の「前回受信したコマンドの番号」に **-1** を載せて、番号を忘れたことを伝えます。
  - 番号は、動作コマンド・緊急停止・アラームクリア・位置リセットの **すべてのコマンドで、1つの通し番号** を共有します。
  - システムの中では、番号を **64 ビット** の整数で数えます（上限に達することは事実上ありません）。AGV との通信で使える桁数が足りない場合の扱いは、通信の方式（未決事項「外部機器とのやり取りの方式」）と一緒に決めます。

### 予期しない通知の扱い

指示の番号を使って、予期しない通知を次のように見分けて扱います。

| 種類 | 例 | 扱い |
|---|---|---|
| 重複して届いた通知 | 通信の再送で、同じ完了の通知が2回届いた | 無視して、ログに残す。**直前に受け付けた通知と、番号・動作の種類・パネルの ID がすべて同じなら重複** とみなす |
| 古い通知 | 位置リセットで捨てた指示の完了の通知が、あとから届いた | 無視して、ログに残す |
| 実際の状態と食い違う通知 | 今の指示の番号なのに、指示と違うパネルに着いたという通知 | 異常として扱う（下を参照） |
| 順番が飛んだ通知 | まだ完了していない手前の動作を飛ばして、あとの動作の完了が届いた | 異常として扱う（下を参照） |

順番が飛んだかは、次のように見分けます。

- **動作コマンドどうし**：コマンドの番号ではなく、**動作の予定のパネルの ID** をもとに見分けます。届いた完了の通知のパネルの ID が、次に着くはずのパネルではなく、その先の予定のパネルだったら、順番が飛んだとみなします。
- **1つの動作コマンドの中**：完了の通知には配列の何番目かが入らないので、**届いた順に、配列の前から1つずつ完了した** とみなします。届いた通知の動作の種類とパネルの ID（回転なら動作の種類）が、次に完了するはずの動作と合わなければ、「実際の状態と食い違う通知」として扱います。

### 動作コマンドの受信の確認

- AGV の GET のリクエストには、**前回受信したコマンドの番号** が載っています。システムは、これで **AGV がどのコマンドまで受け取ったか** を判断します。
  - コマンドの番号は **1 から** 1つずつ増やして付けます。
  - AGV が再起動して番号を忘れたときは、最初の GET に **-1** を載せてきます。**初めて動かすとき**（まだ一度もコマンドを受け取っていないとき）も、-1 を載せてきます。
  - GET に **-1** が載ってきたら、システムは **走りかけだった動作コマンドを渡し直しません**。AGV は再起動の前にその区間を途中まで走っていたかもしれず、渡し直すと実際の位置とずれたまま走るおそれがあるためです。予約は保ったまま、ユーザーの位置リセットを待ちます（「AGV からの完了の通知」の節の再起動の扱いを参照）。
- 動作コマンドの **受信の完了の通知** は、**ログに残すだけ** にします。受け取ったかどうかの判断には、GET に載っている番号を使います。
- 渡した動作コマンドについて、次の GET に載っている番号を見て、次のように扱います。
  - **その動作コマンドの番号まで受け取っている**：受け取ったものとみなします。受信の完了の通知が届かなくても、**もう一度は渡しません**。
  - **まだ受け取っていない**（レスポンスが途中で失われたなど）：**同じ動作コマンドをもう一度渡します**。
- こうすることで、AGV が受け取っていたのに受信の完了の通知だけが失われた場合でも、同じ動作コマンドを2回渡しません。今の AGV は、同じ動作コマンドを2回受け取っても **2回めを無視しない** ので、2回渡すと同じ区間を2回走り、予約していないパネルまで進んでしまうためです。
- 現場にある AGV はアップデートが難しいことが多いので、**通信の仕様は今のまま変えません**（後方互換性を保つ）。この方法は、今の通信の仕様のままで使えます。
| 意味のわからない通知 | 送っていない番号の通知、知らない種類の通知、壊れた内容 | 受け付けずに、ログに残して知らせる |
| 予期しないアラームクリアの完了の通知 | アラームクリアのコマンドを送っていないのに届いた | 無視して、ログに残し、画面で警告する |

**異常として扱うとき**：その AGV に **緊急停止を送り**、「異常」の状態にします。予約はそのまま保ち、**画面で知らせて**、ユーザーの **位置リセットを待ちます**。アラームクリアでは戻れません。システムが AGV の本当の位置を見失っているため、予約していないパネルに AGV がいて、ほかの AGV とぶつかるおそれがあるからです。
- 「異常」の状態のときに届いた完了の通知も、**番号と中身が指示と合っていれば受け付けて、位置を更新** します（異常にする直前に AGV が終えていた動作の通知など）。
  - たとえば、番号 5 の通知の中身が食い違って異常になったあとに、中身の合った番号 6 の通知が届いたら、6 を受け付けます。AGV は指示を順に実行するので、**5 も完了したものとみなし**、5 の通知はログに残して無視します。
  - それでも **「異常」は解除しません**。返ってくるパネル ID はシステムが送った ID と同じなので、6 が合っていても、AGV が本当にそこにいる証拠にはならないためです。ユーザーが現場で確かめて、位置リセットするのを待ちます。
- 指示を出した区間は、キャンセルできない以上、AGV がその区間を走ることが確定します。複数台になったときは、指示を出した区間のパネルを **その AGV のために確保** しておく必要があります（「衝突の防止」の節を参照）。

### 緊急停止

- 出した指示はキャンセルできませんが、**緊急停止コマンド** を送れば、AGV を止められます。
- 緊急停止は、**待機中の AGV にも送れます**。**位置がわからない AGV には送れません**。
- **異常**（位置リセット待ち）のときに緊急停止しても、**異常のまま** にします（緊急停止中にすると、アラームクリアで走り出せてしまうため）。
- 緊急停止を送ったあとに、**止まる直前に AGV が終えていた動作の完了の通知** が届いたら、受け付けて位置を更新します（緊急停止より前に実際に起きた事実なので）。
- 緊急停止すると、システム上は AGV が **パネルとパネルの間で停止した** 状態になります。
- AGV は、止まるまでに **進んだ距離を把握しています** が、その距離を **システムには通知しません**。
  - このため、システムは AGV が **どの2枚のパネルの間にいるか** までしかわかりません。止まっている間は、**その両側のパネルを使用中** として扱います。
- **アラームクリア** は、ユーザーが **本システムの画面から入力** し、システムから AGV へ **アラームクリアのコマンド** を送ります。
  - アラームクリアをすると、AGV は止まった地点から、内部に持っている残りの指示の **続きを再開** します。動作を終えたら、いつもどおり完了を通知します。
  - AGV は、アラームクリアを終えたら、**アラームクリアの完了を通知** します。
  - システムが **新しい指示（次の区間など）を送るのは、アラームクリアの完了の通知を受けてから** です。

### 位置のリセット

- アラームクリアとは別に、**位置リセットのコマンド** があります。システムから AGV に対して、**位置（パネルと絶対角度）を上書き** します。
- 位置リセットを受けた AGV は、**自分のアラームをクリア** し、**内部に持っている指示を破棄** します。
- **ほかの AGV が予約しているパネルには、位置リセットできません**（ほかの AGV がそこを通る予定なので、ぶつかるおそれがあるため）。受け付けなかったときは、画面で知らせます。
- AGV は、**動作中（走行中やキャリアの上げ下げ中）は、位置リセットを受け取りません**。
  - このため、システムは、AGV が動作中なら **位置リセットを受け付けず**、画面で「先に緊急停止してください」などと知らせます。緊急停止で止まったあとなら、位置リセットできます。
  - キャリアの上げ下げの途中で緊急停止し、そのあと位置リセットをしたときは、キャリアは途中の高さで止まっています。システムは **「キャリアが下がっている」** として扱い、上げるコマンドで上げるまで走らせません。
  - このため、位置リセットのあとは、残っていた指示を走りません。システムは、上書きした位置から経路を求め直します。
- システムが新しい動作コマンドを渡すのは、**位置リセットの完了の通知を受けてから** です。

### まだ AGV に渡していないコマンドの取り下げ

- コマンドは、AGV が次に取りに来たときに渡すので、作ったけれどまだ渡していないコマンドがあり得ます。
- **緊急停止** や **位置リセット** をするときと、**AGV からエラーの通知** が届いたときは、まだ AGV に渡していない動作コマンドを **取り下げます**（「指示はキャンセルできない」は、AGV が受け取ったあとの話なので、渡す前なら取り下げられます）。
  - レスポンスで渡したばかりで、AGV が受け取ったかまだわからない動作コマンドは、いったん保留にします。次の GET で **受け取っていなかったとわかれば取り下げ**、受け取っていれば AGV が持っているものとして扱います。
  - 緊急停止やエラーで取り下げた区間は、**アラームクリアの完了の通知を受けたあとに、新しい番号で渡し直します**。
- GET に **-1** が載ってきた（AGV が再起動した）ときは、まだ渡していない **位置リセットのコマンドだけを渡します**。まだ渡していない緊急停止やアラームクリアは、渡さずに捨てます（再起動した AGV は止まっていて、指示も持っていないため）。その AGV は、「異常」と同じく、位置リセットを待つ状態にします。

### そのほかの通知の扱い

- **予期しない位置リセットの完了の通知** は、無視して、ログに残し、画面で警告します。
- すでに「異常」のときに **中身の合わない通知** が届いたら、無視して、ログに残します。緊急停止はすでに送っているので、もう一度は送りません。
- 「異常」のときに中身の合った完了の通知を受け付けたら、位置は更新しますが、**後ろのパネルの予約は解放しません**（異常のときは予約を保つため）。
- **すでに走り終えた動作コマンド** の番号で完了の通知が届いたら、遅れて届いた重複とみなして、無視して、ログに残します。

### 衝突の防止

- AGV が複数台になったとき、**衝突を防ぐのはシステムの役割** です（今回は1台です）。
- 隣り合うパネルに停車してもぶつからず、**回転中も隣のパネルにはみ出しません**。このため、**1枚のパネルに AGV を1台だけ** にすれば、停車中・回転中の衝突は起きません。
- 通行予定のパネルを **予約済みの AGV を優先** します。予約されたパネルには、ほかの AGV は入れません。

### デッドロックの防止

指示はキャンセルできず、AGV は自分では避けられません。このため、予約済みを優先するだけでは、1本道で向かい合ったときや、複数台が輪になって互いを待ったときのデッドロックを防げません。次の組み合わせで防ぎます。

#### 基本：通る順番を守り、区間ごとに予約する

- デッドロックは、**全台の経路の計画**（下の「全台の経路の計画」）で防ぎます。計画から、パネルごとの「通る順番」を取り出し、それを守らせます。
- 予約は、**区間ごと** に取ります（区間は、回転で区切った、まっすぐ進むひとまとまりで、走行の指示を渡す単位です）。
  - 次の区間のパネルが、**すべて自分の番になっていて**（先に通る予定の AGV が通り終えていて）、**予約できたとき** だけ、その区間の指示を AGV に渡します。
  - 通路の途中で止まって待つことがありますが、通る順番を守っているので、デッドロックにはなりません。
  - ゴールまでまとめて押さえないので、ほかの AGV の道を塞ぐ時間が短くなります。
- 渡した指示は取り消せないので、AGV に渡した区間のパネルは、その AGV が通り終えるまで予約したままにします。
- 予約は、AGV から通知される **十字の検出をきっかけに、通過したパネルから順に解放** します。
  - 着いたパネルより後ろのパネルの予約を解放します。ただし、**同じ経路の中で、あとでもう一度通るパネル** は解放しません（例：A → B → C → B → D なら、C に着いても B は手放しません）。
  - 経路を走り終えたら、**今いるパネルだけ** を予約した状態にします。

#### 保険：デッドロックを検出して解消する

- 全台の計画の通る順番を守らせれば、理屈の上ではデッドロックは起きません。それでも、計画の不具合や、計画の外で動く AGV（マニュアルでの、計画と食い違う動かし方など）に備えて、保険を残します。
- どの AGV がどの AGV を待っているか（待ちのグラフ）を見張ります。
- 待ちが輪になったら、**画面で知らせたうえで、全台の計画を立て直します**。立て直しても解けなければ、そのうち1台を **退避場所（待機パネル）へ逃がして** 解消します。
- 退避の指示もキャンセルできないため、退避先までの予約が取れることを確かめてから出します。

#### 一方通行（設定で選べる）

- レイアウトで決められる現場では、通路ごとに **進む向きを設定で決められる** ようにします。向かい合いそのものを起こさないためです。
- 一方通行にするかどうかは、構成ごとの設定で切り替えます。

#### 全台の経路の計画

1台ずつ経路を求めて予約するだけでは、予約がほかの AGV の道を塞ぐことがあります。そこで、**全台の経路をまとめて計画** します（今は AGV が1台ですが、先に土台を作ります）。

- **重視すること**：まず **止まらない（デッドロックしない）計画** を作り、時間に余裕があれば、全体の所要時間を縮めるように改善します。
  - 改善には、計画を立てるたびに **時間の上限**（設定値。既定は **200ミリ秒**）を設けます。止まらない計画ができたら、残りの時間で改善を試み、上限が来たら、その時点で一番よい計画を使います。
  - 上限は、AGV が1枚のパネルを進む時間（例：800mm を 500mm/秒で約1.6秒）より十分に短くします。計画を立てている間は、AGV への新しい指示が出せないためです。
  - 改善の物差しは、**必要時刻に対する遅れの合計**（それぞれの搬送の必要時刻より遅れて着くぶんを、全台ぶん足したもの）です。これが同じなら、**全台の到着時刻の合計** で比べます。全員が間に合って遅れが同じでも、効率で差をつけるためです。
  - 必要時刻のない移動（充電に向かう、待機パネルへどくなど）は、遅れには数えず、到着時刻の合計の側で数えます（いくらでも待たされることがないように）。
  - 改善では、**計画の順番を入れ替えて試します**（順番が同じなら、先の AGV の経路はすでに一番早いので、改善の余地がほとんどないため）。物差しがよくなる場合に限り、必要時刻の早い順とは違う順番の計画を選びます。遅れの **合計** は増えませんが、ある AGV の遅れが減るぶん、別の AGV が遅れる計画を選ぶことはあります。
  - 改善は、**試す順番を決めておき**（順番の隣り合う2台の入れ替えを、前から順に試し、よくなれば採用して続ける）、時間の上限で打ち切ります。同じ状況なら試す順番は同じで、違うのは「どこまで試せたか」だけです。
  - 入れ替えた結果、**塞がれて行けない AGV が増える計画は選びません**。遅れや到着時刻を比べる前に、計画できた AGV の数で比べます（行けなくなった AGV は遅れにも到着時刻にも入らず、数字の上ではよく見えてしまうため）。行き先が通路の上の通常パネルで、そこに止まり続ける AGV が、ほかの AGV の通り道を塞ぐ場面などで効きます。
- **計画の立て方**：AGV に順番を付け、先の AGV から順に「どのパネルを、いつ通るか」を決めます。あとの AGV は、先の AGV を避けて経路を求めます。
  - すでに AGV に渡した走行の指示（取り消せない）と、止まっている AGV がいるパネルは、動かせないものとして一番先に固定します。
  - 残りは、**搬送の必要時刻が早い AGV から** 順に決めます。搬送のない移動（充電に向かう、待機パネルへ移るなど）は、搬送の AGV のあとにします。
  - 必要時刻が同じ AGV どうしと、搬送のない移動どうしは、**頼まれた順**（先に動かす頼みが来た AGV から）にします。配車は、AGV を動かすときに、搬送の必要時刻も交通整理に渡します。
- **計画と実際の動きのずれ**：時刻ではなく、**パネルごとの「通る順番」** を守らせます。AGV は、そのパネルを自分より先に通る予定の AGV が通り終えるまで、そのパネルに入りません（パネルの予約で守らせます）。遅れた AGV がいても、ほかの AGV は待つだけで、順番が守られるので、デッドロックしない計画なら、実際もデッドロックしません。
- **計画を立てる（立て直す）とき**：AGV を動かす頼みが来るたびに、**全台の計画を立て直します**。AGV が止まったときと、改善するときも、同じく全台を立て直します。
  - **塞がれて待っている AGV がいるとき** は、次のときにも立て直します（新しい頼みが来ないと、いつまでも試し直されないため）。
    - ほかの AGV が行き先に着いた（道が空いたかもしれない）
    - 止まっていた AGV が再開した（アラームクリア、位置リセットの完了）
    - コントロールステータスが変わった（ロックやマニュアルが解けた、など）
- **止まった AGV の扱い**：止まった AGV が動かないと、その AGV のあとに同じパネルを通る予定の AGV が待ち続けるので、止まった AGV を **動かない障害物** として、ほかの AGV の計画を立て直します。
  - **異常**（位置リセット待ち）になったら、すぐに立て直します。
  - **緊急停止中**（アラームクリアで再開できる）は、まず待ちます。止まってから **一定時間**（設定値。既定は **1分**）たっても再開しなければ、立て直します。
  - 止まった AGV がいるパネルの予約は保ちます。その AGV の向こう側にしか行けない AGV は、待つしかありません。
  - 止まった AGV が使っているパネルは、パネルの上なら、そのパネル。パネルとパネルの間で止まっていれば、両側のパネルです。
  - **異常** で障害物にした AGV は、**行き先と残りの経路を捨てます**。位置リセットのあとに動かすときは、配車（ユーザーの「やり直す」）が、改めて動かす頼みを出します（位置リセットで AGV の指示が消えることと、そろえるため）。
  - **緊急停止中** で障害物にした AGV は、**行き先を覚えておき**、アラームクリアのあとに、その続きの計画を立て直します（搬送も一時停止で、再開する決まりのため）。
- **AGV が動いている間に使っているパネル**：止まっている（待っている）ときと、その場で回転しているときは、そのパネル。隣のパネルへ前進・後退しているときは、**出発したパネルと着くパネルの両方**（動き出してから着くまで）。同じ時刻に、同じパネルを2台が使わないように計画します。
- **行き先に着いた AGV と、行き先のない AGV**：次の頼みが来るまで、そのパネルに **止まり続ける** ものとして計画します。あとの AGV は、そのパネルを、その時刻から先はずっと通れないものとして避けます（行き先のない AGV が通路を塞いでいて、動かせる状況なら、待機パネルへ動かします。上の「搬送も移動もない AGV」を参照）。
- **順番があとの AGV が、先の AGV の通り道にいるとき**：まだ計画していない AGV の今いるパネルは、先の AGV にとって「ずっと塞がれている」とみなします。先の AGV が、そのせいで行けなければ、**塞いでいる AGV の順番を繰り上げて**、計画し直します（どかさないと誰も進めないので、必要時刻の順番が一部入れ替わるのはやむを得ないとします）。繰り上げても行けなければ、「今は塞がれていて行けない」とします。
- **計画する時間の長さの上限**：あとの AGV は、先の AGV が通り過ぎるのをその場で待って避けます。待ち続けても行けないこともあるので、計画する時間の長さに上限（設定値。既定は **10分**）を設け、上限までに行き先に着ける計画が見つからなければ、「今は塞がれていて行けない」とします。
  - 上限の目安は、**マップの端から端まで走る時間の、およそ5倍** です（端から端まで2分なら、10分）。長すぎると計算が重くなり、短すぎると、遠くの行き先や、長く待てば行ける AGV が「行けない」になります。
- **計画が立てられない AGV**：原因によって扱いを分けます。ほかの AGV に塞がれているかどうかは、塞いでいる AGV を取り除いたら経路があるかどうかで見分けます。
  - **マップの上に、そもそも経路がない**（別の島にいる、一方通行で行けないなど）：**経路が見つからない** として頼みを受け付けず、画面で知らせます（搬送の途中なら、搬送を中断します）。
  - **今は、ほかの AGV に塞がれていて行けない**（ロック中やマニュアル中の AGV、止まった AGV が通路を塞いでいるなど）：**待ちます**。画面で知らせ（予約が取れず止まっている）、計画を立て直すたびに、また試します。
- **搬送も移動もない AGV**：通り道を塞いでいて、**動かせる状況** なら、近くの空いている待機パネルへ動かす計画も一緒に立てます。動かせなければ、動かない障害物として扱います（計画でほかの AGV の通り道を塞いでいたら、邪魔になったとします）。
  - 動かす先は、**移動コスト（所要時間）が一番近い、空いている待機パネル** です。同じ近さなら、パネルの ID の順で選びます。空いているとは、ほかの AGV がいない、予約していない、行き先にしていない、全台の計画でほかの AGV が止まり続けることになっていない、のすべてを満たすことです。行ける、空いている待機パネルがひとつもなければ、動かさずに、動かない障害物として扱います（塞がれた AGV は待ち、画面で知らせます）。
  - 動かせる状況とは、次をすべて満たすときです：待機中（走行中、キャリアの上げ下げ中でない）、緊急停止中・異常・位置不明・位置リセット中でない、キャリアが上がっている、ほかの頼み（充電に向かうなど）を受けていない。
  - **充電中** の AGV は動かしません（充電が止まり、充電切れで止まるおそれがあるため）。充電ピンのあるパネルは行き止まりなので、もともと通り道は塞ぎません。
  - **ものを載せたまま待っている** AGV（積み込んだあとに搬送を取りやめた）は、動かせます。載せたまま待機パネルへ移るだけで、ものの所在は「AGV の中」のまま変わりません。
- **作りの置き場所**：全台の計画は、**状態を持たない計算の新しいコンテキスト `FlowHub.PathPlanning`** に置きます。
  - 交通整理が、AGV の位置、渡した指示、止まっている AGV などを引数で渡して呼びます（交通整理 → PathPlanning）。
  - PathPlanning は、**何にも依存しません**（ルーティングと同じ）。グラフ、姿勢、速さなども、自分専用の入力の形として持ちます。ルーティングを既存システムのルート計算に差し替えても、影響を受けないようにするためです。
  - 1台の経路を求めるのはルーティング（`FlowHub.Routing`）、全台の経路をまとめて計画するのは PathPlanning です。

### コントロールステータス

AGV ごとに、システムがどこまで指示を出すかを表す **コントロールステータス** を持ちます。コントロールステータスは **システムが持ち**、**ユーザーが画面から切り替えます**（AGV 本体には持たせず、AGV との通信の仕様は変えません）。

- コントロールステータスは **DB に保存し、再起動しても残します**（切り離した AGV が、再起動でオートに戻らないようにするため）。
- 新しく登録した AGV は、**切り離し** から始めます。マップの上に置いて位置リセットをしてから、ユーザーが切り替えます。

| ステータス | 意味 | 全台の計画での扱い |
|---|---|---|
| **オート** | システムの判断で指示を出す（搬送の割り当て、充電、邪魔なときの移動など） | 計画の中で動かす |
| **割り当て停止** | オートで動くが、**新しい搬送は割り当てない**。今の搬送は終える | 計画の中で動かす（新しい搬送は来ない） |
| **マニュアル** | システムの判断では指示を出さず、**ユーザーが、オートと同じコマンドを、システムを通して送る** | システムが行き先を決めない AGV として、今いるパネルと、ユーザーのコマンドで動いている先を塞いでいるものとして扱う |
| **ロック** | マップの上にいるが、**システムもユーザーも何も指示しない** | 今いるパネルを塞いでいるものとして扱う。予約も保つ |
| **切り離し（運用外）** | マップの上にいない（修理のために運び出したなど） | いないものとして扱う。予約も外す |

- マニュアルのコマンドも、システムを通るので、AGV の位置はこれまでどおり完了の通知で把握できます。
- マニュアルのとき、ユーザーは次の2つの動かし方を選べます。どちらの場合も、キャリアの上げ下げ、緊急停止、アラームクリア、位置リセットも送れます。
  - **行き先のパネルを指定する**：経路はシステムが求め、全台の計画の中で、ほかの AGV を避けて動かします。
  - **1つずつの動作を指定する**：「隣のパネルへ前進」「隣のパネルへ後退」「この角度へ回転」を、1回ずつ送ります。細かく合わせたいときに使います。
  - どちらも、マップの決まり（受け渡しパネルや待機パネルには前進でしか入れない、など）とパネルの予約を、オートと同じく守らせます。守れないコマンドは、受け付けずに画面で知らせます。
- マニュアルのコマンドも、オートと同じく、**動く先のパネルを予約できたときだけ** AGV に渡します。予約できなければ、受け付けずに画面で知らせます（ほかの AGV とぶつからないようにするため）。
- 切り替えられる条件は、次のとおりです（走行の指示は取り消せないので、走っている途中の切り替えを制限します）。

| 切り替え先 | 切り替えられる条件 |
|---|---|
| オート | いつでも |
| 割り当て停止 | いつでも（今の搬送は終える） |
| マニュアル | **走っていないとき**（待機中か、緊急停止中）だけ |
| ロック | **走っていないとき** だけ |
| 切り離し | **ロック中** のときだけ（先にロックで止めてから運び出す）。切り離したら、予約を外す |

- **切り離しから** ほかのステータスへ切り替えるときは、**位置リセットを必須** にします（切り離していた間に、マップの上のどこに置かれたかわからないため）。切り離し中の AGV にはコマンドを送らないので、切り替える操作で **位置（パネルと絶対角度）を一緒に指定** してもらい、切り替えと同時に位置リセットを送ります。位置リセットの完了の通知を受けたら、切り替えが済みます。
  - 指定した位置のパネルを **ほかの AGV が予約していたら、切り替えを受け付けず**、切り離しのままにします（画面で知らせます）。ユーザーは、パネルが空いてからやり直します。
- 緊急停止中の AGV を **マニュアルかロックに切り替えたら、行き先と残りの経路を捨てます**（システムの判断では、もう動かさないため）。充電ポートへ向かっていたなら、オートか割り当て停止に戻したときに、充電ポートを探し直します。
- **マニュアル、ロック、切り離しの間に充電が必要になったら**、充電ポートへは向かわせません（システムの判断では動かさないため）。オートか割り当て停止に戻したときに、充電ポートを探して向かわせます。
- オート以外（マニュアル、ロック、切り離し）に切り替えるときに、その AGV に **割り当て済みの搬送があれば、切り替えられません**。先に「割り当て停止」で搬送を終わらせるか、搬送を取りやめてから切り替えます。
- **ロック中** でも、安全と復旧のための次のコマンドは扱いを分けます。**切り離し中** の AGV には、どのコマンドも送りません（マップの上にいないため）。

| コマンド | ロック中 | 理由 |
|---|---|---|
| 緊急停止 | **受け付ける**（どのステータスでも受け付ける） | 止める操作は、いつでもできるほうが安全なため |
| アラームクリア | 受け付けない | AGV が残りの指示の続きを走り出すため |
| 位置リセット | **受け付ける** | 走り出す操作ではなく、位置を教えるだけなので |
| キャリアを上げる | 受け付けない | AGV が動くため |

## AGV の割り当て

- AGV は **本システムが直接制御します**（運行管理システムなどを間に挟みません）。
- 走行距離を求めるための **マップやルートの情報は、本システムが持ちます**。
- AGV をあるパネルへ動かすように頼まれたとき：
  - **経路が見つからなければ、受け付けず、画面で知らせます**。
  - **予約が取れなければ（ほかの AGV がいれば）、待って、予約が空いたら出発します**（デッドロックの防止と一緒に作ります）。
  - **すでにそのパネルにいれば、動かさずに、すぐ「着いた」と知らせます**。
- 搬送がないとき、AGV は **最後の受け渡しパネルにとどまります**。全台の計画で、ほかの AGV の通り道を塞いでいたら（邪魔になったら）、動かせる状況なら、待機パネルへ移します（「全台の経路の計画」の節を参照）。
- 搬送を割り当てられる AGV は、次の条件をすべて満たすものです。
  - **待機中** であること。搬送中の AGV に、次の搬送を先に割り当てておくことはしません（複数台での効率は今後の課題。未決事項を参照）。
  - 緊急停止中・異常・位置不明・位置リセット中でないこと。
  - 充電残量が、**充電に向かう値を下回っていない** こと（ちょうどその値なら割り当てます）。一度充電に向かった AGV は、**割り当てに戻す値以上に回復するまで** 割り当てません。どちらの値も設定で変えられます（「充電」の節を参照）。
  - 消耗品搬送専用の AGV は、**搬送の要求が求めるキャリアの種類と、AGV のキャリアの種類が合う** こと。
  - AGV の今の位置と向きから、搬送元の受け渡しパネルまでの **経路が見つかる** こと（別の島にいる AGV などは外します）。
- 割り当てられる AGV がいなければ、搬送の要求は **待ち行列に残します**。AGV が空いたとき、充電が回復したとき、新しい要求が来たときに、割り当てをやり直します。
  - 「AGV が空いたとき」には、搬送を完了したとき、アラームクリアが完了して待機中に戻ったとき、位置リセットが完了して待機中になったとき、充電を終えて割り当てに戻したときを含みます。
  - 待ち行列は、**必要時刻が早い順、同じなら頼まれた順** に並べます（必要時刻の計算は未定。それまでは不足が起きた時刻で代わりにします）。

### 搬送の流れ

- 1回の搬送は、次の順に進みます。届けるときも回収するときも同じ流れで、どちらで積み込み、どちらで降ろすかが違うだけです。
  1. 待ち（割り当て待ち）
  2. 搬送元へ移動
  3. 搬送元でキャリアを下げる → 受け渡し → キャリアを上げる（ここで「積み込んだ」）
  4. 搬送先へ移動
  5. 搬送先でキャリアを下げる → 受け渡し → キャリアを上げる（ここで「降ろした」）
  6. 完了（AGV は搬送先の受け渡しパネルにとどまり、待機中に戻る）
- 搬送の流れは、**配車の中で1か所** にまとめて進めます。
- 搬送の途中で、搬送元や搬送先への **経路が見つからなかったら**、搬送を **中断** にして、画面で知らせます（異常のときと同じ扱い）。
- 搬送や充電の移動で、**塞がれていて行けない**（全台の計画が立てられない）ときは、その場で待ち、**画面で警告** します。計画を立て直すたびに、また試します。全台の計画どおりの **順番待ち**（先に通る予定の AGV が通り過ぎるのを待っている）は、ふつうの動きなので、警告しません（長く待つ原因は先の AGV が止まったことなので、それは止まった AGV の側で知らせます）。
- 搬送の段階と合わない知らせ（搬送元へ移動している途中に「キャリアが上がった」が届いた、など）は、**状態を変えず、ログに残して画面で警告** します。
- 装置やステーションが受け渡しを終えない（完了の通知が来ない）ときは、**待ち続けます**（時間を区切るかどうかは、未決事項「異常時の扱い」で決めます）。
- 頼んだ側は、**割り当て前（待ち行列にある）の搬送の要求を取りやめられます**。
- 割り当てたあとも、**AGV へのコマンドの単位で** 取りやめられます。
  - **AGV がすでに受け取ったコマンドは、止められません**。まだ渡していないコマンドを取り下げ、AGV は受け取ったコマンドを終えたところで止まります。走行中なら、今走っている区間（動作コマンド）を終えたところで止まるので、通路の途中のパネルで止まることもあります。
  - **積み込んだあとでも取りやめられます**。AGV は、ものを載せたまま **その場で待機し、システムからの指示を待ちます**。
    - 取りやめたときに AGV が持っているものは、不足の判断をやり直した結果、**どこかの装置で必要なら、その装置へ直接届けます**。**届ける先がなければ、ステーションに返します**。持っているものを届けるか返すまで、その AGV にほかの搬送は割り当てません。
    - 返すステーションは、**ステーションの選び方のルール** で決めます（未決事項「ステーションの選び方のルール」）。
    - 届けるときや返すときの指示は、**新しい搬送の要求** として出します。搬送元は、その AGV 自身です（積み込みを飛ばして、搬送先へ向かう）。
  - これは、**もっと効率のよい経路が見つかったときに、途中で変えられるようにする** ためでもあります。
  - **受け渡しの途中**（キャリアを下げている間）に取りやめたときは、受け渡しの相手に **搬送の許可をまだ出していなければ、許可を出さずにキャリアを上げて** 止まります。**許可を出したあとなら、受け渡しを最後まで終えて、キャリアを上げたところで** 止まります。
  - AGV が止まったら、**止まったパネル以外の予約を解放** します。
  - 取りやめの知らせを受けたら、消耗品の管理は、届ける途中の数からその消耗品を外し、**不足の判断をやり直します**。そのとき、**AGV が持っているものも、不足を補うのに使えます**。
- 搬送の途中で AGV が止まったときは、次のように扱います（細かい扱いは未決事項「異常時の扱い」で決めます）。
  - **緊急停止中**（アラームクリアで続きを走れる）：搬送も **一時停止** にし、アラームクリアのあと、その続きから進めます。
    - 一時停止中に届いた知らせ（緊急停止の直前に搬送元に着いていた、受け渡しの完了が届いた、など）は、**状態を進めます**（事実なので記録します）。ただし、**次のコマンドは、アラームクリアのあとまで出しません**。受け渡しの相手への **搬送の許可** も、同じく出しません（AGV が止まっている間に、装置がキャリアへものを出し入れしないようにするため）。
    - 「積み込んだ」「降ろした」という知らせ（イベント）は、受け手がいないので出しません（イベントは最小限にするため）。必要になったら加えます。
  - **異常**（位置リセットが必要）：搬送を **中断** にし、画面で知らせます。位置リセットのあと、ユーザーが **やり直すか取りやめるか** を選びます。
    - 「やり直す」は、**今いる段階の続きから** 進める方向で考えます（積み込んだあとなら、AGV に消耗品が載っているはずなので、搬送先へ向かう）。
- 搬送に使える AGV が複数台あるときは、**搬送元に近い AGV から割り当てます**。近さ（移動コスト）は、AGV の今の位置と向きから、搬送元の受け渡しパネルまでの経路で測ります。
  - 近さ（移動コスト）が同じ AGV が複数あるときは、**これまでの累計の走行距離が短い AGV** を選びます。AGV ごとの消耗をならすためです。累計も同じなら、AGV の ID の順で選びます。
  - 累計の走行距離は、受け付けた前進・後退の完了の距離を足して、システムが数えます。
- 「近さ」は、**走行距離と回転を合わせた移動コスト** で測ります。AGV は走りながら曲がれず、曲がるたびにその場で回転するため、走行距離だけでは実際の移動の手間とずれるからです。
  - 移動コストは、**所要時間** に換算して求めます。AGV の前進速度・後退速度・回転速度は **固定値** で、**AGV の種類ごとの設定** として持ちます。次の式で計算できます。
    - 移動コスト ＝ 前進の距離 ÷ 前進速度 ＋ 後退の距離 ÷ 後退速度 ＋ 回転の角度の合計 ÷ 回転速度
    - 回転の角度は、AGV が近い回りで回るため、**回転前と回転後の角度の差のうち小さいほう**（最大 180度）で数えます。
  - 充電ポートを選ぶときの「近さ」も、同じ移動コストで測ります。
- 移動コストが同じ経路が複数あるときは、**回転の少ないほう**、それも同じなら **後退の少ないほう** を選びます（回転のたびに止まり、後退は前進より遅いため）。それでも同じなら、どれを選ぶかは決めません。全台の経路の計画でも、同じ選び方をします。
- 消耗品搬送専用 AGV は、キャリアが AGV に固定で、キャリアは加工の種類ごとに専用です。このため、**専用 AGV が運べる加工の種類は1台ごとに決まっています**。割り当ての候補は、運ぶ消耗品の加工の種類に合う AGV に絞ります。

### 充電

- 充電残量は、**残量が変化したタイミングで AGV から通知** されます。
  - システムを起動した直後などで、まだ一度も通知が来ていない AGV は、**充電は足りているものとみなして** 割り当てます。最初の通知が来たら、その値で判断します。
- AGV の **充電残量が 20% を下回ったら**、その AGV には搬送を割り当てません。代わりに **充電ポートへ行って充電するよう指示** します。
- 搬送の途中で下回ったときは、**その搬送を完了してから** 充電に向かわせます。
- 充電ポートは **複数あります**。**移動コストで近い充電ポート** に向かわせます（「AGV の割り当て」の節を参照）。
  - 一番近い充電ポートを **ほかの AGV が使っている（予約している）ときは、次に近い、空いている充電ポート** へ向かわせます。
  - **行ける充電ポートがひとつもない**（空いていない、経路が見つからない）ときは、その場で待ち、充電ポートが空いたら向かわせます。**画面で知らせます**。
- **待機中** に充電残量が下がって、充電に向かう値を下回ったときも、充電に向かわせます。
- 充電に向かう途中で、充電残量が割り当てに戻す値以上になったとき（通知の誤りなど）も、向かうのはやめません。**充電ポートに着いてから**、割り当てに戻すかを判断します。
- 充電を終えた（割り当てに戻す値以上になった）AGV は、**充電ポートにとどまり**、待機中に戻ります。
- 充電ポートへ向かっている途中で AGV が **「異常」** になったら、充電の状態を **「充電ポートを探す」に戻し**、位置リセットが完了して待機中になったときに、もう一度充電ポートを探して向かわせます。
- 充電ポートは、**充電ピンを設置した受け渡しパネルか待機パネル** です（「パネルの種類」の節を参照）。
- 充電ピンのあるパネルに止まっている間は、**受け渡しの最中や待機中でも充電します**。充電に向かう値を下回らなくても、止まるたびに少しずつ充電されます。
- 充電ピンのあるパネルに止まっているときに充電残量が充電に向かう値（20%）を下回ったら、**その場から動かず、そのまま充電** します。割り当てに戻す値（80%）まで回復したら、また動けるようになります。
  - 受け渡しパネルで止まった場合、その間は受け渡しパネルがふさがり、その装置やステーションとの受け渡しができません。
  - ただし、**搬送の途中** なら、充電ピンのあるパネルにいても、その場では充電しません。**搬送を終えてから** 充電します（届けることを優先します）。搬送を終えたパネルに充電ピンがあれば、そこで充電し、なければ充電ポートへ向かいます。
- 充電残量が **80% まで回復したら**、搬送の割り当てに戻します。
- 充電に向かう値（20%）と、割り当てに戻す値（80%）は、**AGV の種類や構成ごとに設定で変えられる** ようにします。
  - システム全体の **既定値** を持ち、設定で変えられます（最初の値は 20% と 80%）。
  - AGV の種類ごとの値は **省略できます**。省略したら、**種類を登録するときに、そのときの既定値で埋めて保存** します。
    - 保存する値はいつも具体的な数になるので、保存するときに「割り当てに戻す値は、充電に向かう値以上」を確かめます。決まりを破るなら、保存しません（既定値も同じです）。
    - あとで既定値を変えても、**登録済みの種類の値は変わりません**。既定値の変更は、そのあとに登録する種類から効きます。
  - どちらも 0〜100% の範囲です。割り当てに戻す値は、**充電に向かう値以上** でなければなりません（同じ値はかまいません）。

## 段取り替え

- 段取り替えは、**搬送のきっかけでも、ストッカーの設定を書き換えるきっかけでもありません**。
- 装置がこれから加工するデバイスのデータから、どの消耗品を使うかを決める **対応表は装置が持ちます**。このため、段取り替えは **装置からのリクエスト** で始まります。
- リクエストの中身は **必要な品種だけ** です。必要な品種が複数あるときは、**品種ごとに別々のリクエスト** が届きます。
- システムは、リクエストされた品種が **ストッカーの設定に含まれているか** を確かめます。
  - 設定の個数が **1個以上** の品種を「含まれている」とします（0個の品種は含まれていません）。ストッカーの設定をまだしていない装置では、どの品種も含まれていません。
  - **含まれていないとき**（今の設定ではそのデバイスの加工が成り立たないとき）は、**上位システムにエラーを通知** します。上位システムがない構成では、**ユーザーに通知** します。
    - エラーは、上位システムとのやり取りのポートに加えた「段取り替えのエラー」で知らせます。上位システムがない構成では、ユーザーに知らせる実装に差し替えます。
    - 装置へは、結果を返しません。
    - 同じ品種のリクエストが繰り返し届いたときは、**届くたびに確かめ**、含まれていなければ、そのたびにエラーを知らせます。
  - 設定には含まれていて、**ストッカーにある個数が足りないだけ** のときは、エラーにしません。通常の不足として、**供給を待ちます**。
- システムはストッカーの設定を書き換えません。設定を変えるのはユーザー（顧客）です（「装置のストッカー」の節を参照）。
- ユーザーが設定を変えると、設定との差分が「不足」と「設定にない消耗品」として現れ、配車のきっかけの表のとおりに届ける・回収するの搬送が動きます。段取り替え専用の搬送の仕組みは作らず、処理をシンプルに保ちます。
- 設定にない消耗品は、廃棄リクエストを待たずに **システムが自動で回収しに行きます**。
- 設定の変え方によっては、一度回収した消耗品をまた届けるといった **ムダな搬送が起きることがありますが、許容します**。段取り替えはあまり発生せず、ストックの設定は顧客の責任だからです。

## 消耗品の補充

- 装置へ届ける消耗品は、**ステーション** から持っていきます。
- ステーションに必要な消耗品がない場合、システムは **上位システムに補充のリクエストを送ります**。上位システムがない構成では、**ユーザーに通知して** 補充を促します。
- 補充されるまで、その搬送は **待ち行列に残して待機** します。補充されたら **自動的に動き出します**。

## 上位システムとの連携

- 上位システムは、**ない構成もあります**。
- 現時点で上位システムとやり取りするのは、次の3つだけです。
  - **ステーションへの補充リクエストを送ること**
  - **段取り替えのエラーを通知すること**（リクエストされた品種がストッカーの設定にないとき）
  - **ステーションからの取り出し（出庫）の指示を受けること**
- 将来、在庫状況などシステムの現在の状態を **上位システムに通知する仕組み** が必要になるかもしれません。後から加えられるよう、上位システムとのやり取りはポート（インターフェース）として切り出しておきます。

## システムの構成による違い

次の点は、システムの構成によって変わります。

- ステーションの数と、それぞれのスペースの数（入出庫口のようにスペースが1つのものもあります）
- 装置ごとのストッカーの数と、ストッカーごとのスロットの数
- ステーションの選び方のルール
- マップとルート（パネルの種類、充電ピンの有無、通路ごとの一方通行を含む）
- AGV の充電に向かう値と、割り当てに戻す値（AGV の種類ごと）
- AGV の前進速度、後退速度、回転速度（AGV の種類ごと）
- 上位システムの有無
- 装置の中でのプレートの扱い

構成の違いは設定で切り替えられるようにし、ドメインのロジックに構成ごとの分岐を散らばらせない設計にします。

## システムの規模

| 対象 | 今回 | 将来の最大（参考値） |
|---|---|---|
| 装置 | 1台 | 100台程度 |
| AGV | 1台（消耗品搬送専用 AGV） | 100台程度 |
| ステーション | 1台 | 100台程度 |

- 今回は1台ずつですが、将来拡張される可能性があります。台数が増えても作り直さずに済む設計にしておきます。

### 今回の対象

- 搬送の向きは、**ステーション → 装置**（届ける）と、**装置 → ステーション**（回収する）の2種類だけです。
  - 装置から装置、ステーションからステーションへの搬送は、今後の課題です（未決事項を参照）。

- AGV は消耗品搬送専用 AGV の1台だけなので、今回は **プレート搬送を使いません**。
- 専用 AGV が運べる加工の種類は1台ごとに決まっているため、今回扱う **加工の種類は1つだけ** です。
- プレート搬送と複数の加工の種類は、将来の拡張に備えて仕様として残しておきます。今回の対象外でも、後から加えられる設計にしておきます。

## 消耗品の所在（状態）

消耗品は、次のいずれかの場所にある状態を持ちます。

| 所在 | 説明 | システムによる管理 |
|---|---|---|
| 加工部 | 装置内で消耗品を使って加工する場所 | 管理しない（存在を描画するだけ） |
| ストッカー | 装置内で消耗品を保管する場所 | 管理する |
| 受け渡し部 | 装置と AGV の間で消耗品を受け渡す場所 | 管理する |
| AGV 内部 | AGV のキャリアに載って搬送されている状態 | 管理する |
| ステーション | システムの中と外をつなぐ出入り口で、消耗品をストックする設備 | 管理する |
| 所在不明 | ID の照合エラーで、所在がわからなくなった状態。ステーションで ID が読み取られるまで続きます | 管理する |

- **加工部** の消耗品はシステムの管理対象外です。ただし、そこに消耗品があること自体は画面に描画したいので、その機能はシステムが持ちます。
- プレート搬送の対象の消耗品は、プレートに載った状態で移動します。システムは、消耗品がどのプレートに載っているかと、プレートがどこにあるかを管理します。

## 消耗品の流れ

使用前の消耗品は、ステーションから装置へ運ばれます。回収する消耗品は、同じ経路を逆方向にたどります。

```
ステーション ⇔ AGV ⇔ 受け渡し部 ⇔ ストッカー ⇔ 加工部
```

- **届ける**：ステーション → AGV → 受け渡し部 → ストッカー → 加工部
- **回収する**：加工部 → ストッカー → 受け渡し部 → AGV → ステーション

## 装置から受け取る情報

- 装置は、**加工部**、**ストッカー**、**受け渡し部** に消耗品（プレート）があるかどうかを把握できます。システムはこの情報を装置から受け取ります。
- ただし、ストッカーにある消耗品の **ID は装置にはわかりません**。装置は、システムからの通知をもとに消耗品の ID を推測して動きます。
- 装置は、消耗品を **加工部に取り込むときに ID を照合** します。
- 消耗品を加工部に取り込んだときは、**取り込んだ消耗品の ID を含む通知** が装置から来ます。システムはこの通知で、その消耗品を中古品として扱います。
- 使い終わった中古品は、原則として **元のスロットに戻ります**。戻すスロットは **装置が決め**、**どの消耗品をどのスロットに戻したか** を通知してきます。
  - 取り込んでいる間、元のスロットは **ふだんは空けておきます**（届けるものの入れ先にしません）。
  - ただし、届けるときに空きスロットが足りなければ、**取り込み中の元のスロットも入れ先に使います**。そのときは、装置がほかの空きスロットに戻します。
  - 戻すときに空きスロットがなければ、**装置がエラーを出します**。システムは何もしません（中古品は加工部にあるままとし、戻したという通知で所在を更新します）。
- 取り込みの通知の消耗品が、記録上その装置のストッカーにないとき（別の場所にある、所在不明など）は、照合は装置で済んでいるので、**通知を正として** 加工部・中古品にし、食い違いをログに残して画面で警告します。**未登録の ID** は、品種がわからないので、エラーにします。
- 「戻した」の通知で、戻した消耗品が記録上は加工部になかったり、戻したスロットに記録上は別の消耗品があったりしたときも、**通知を正として** 所在を更新します。スロットにあると記録されていた別の消耗品は、**所在不明** にします。どちらも、食い違いをログに残して画面で警告します。

## ID の照合が合わないとき

装置からの通知は、**照合のエラー** と **交換の完了** の2回に分かれます。

- **照合のエラー**：装置、場所（スロット）、読み取った ID が入ります。システムは、記録上そこにあった ID と読み取った ID を、**どちらもこの時点で所在不明** にします。そのスロットは、交換が済むまで **ふさがっているもの** として数えます。
- **交換の完了**：装置、場所、交換後の消耗品の ID が入ります。

1. 装置が **エラーを発報** します。
2. ユーザーが装置まで行って、消耗品を交換します。
3. **交換後の消耗品**：装置が読み取った ID をシステムに通知します。システムはこの通知で在庫情報を正しい状態にします。
4. **所在不明にする消耗品**：次の **どちらも所在不明** にします。
   - システムがその場所にあると記録していた ID の消耗品（実際にはどこにあるかわからないため）
   - 装置が読み取った、実際にその場所にあった ID の消耗品（交換前の消耗品）
5. 所在不明の消耗品は、ユーザーがステーション（入出庫口）に入れると、ステーションが ID を読み取り、所在が確定します。

- 交換のやり方は、次の2通りです。

| やり方 | 代わりの消耗品 | 照合が合わなかった消耗品 |
|---|---|---|
| **人が現物を交換する** | ステーションから持ってきたもの（登録済み）か、システムの外から持ってきたもの（未登録） | 人が取り出す |
| **人が AGV を使って受け渡す** | ステーションから AGV で運ぶ（登録済み） | AGV で回収し、ステーションに **不明な消耗品** として置く。人が確かめて、何の消耗品かを直せる |

- **人が現物を交換するのは、最終手段** です。不整合があったときは、消耗品をステーションへ運び、**ステーションで現物を確かめられる** ようにします（装置まで行くより、ステーションで操作するほうがユーザーは楽なため）。
- 人が現物を交換したとき、交換後の消耗品が **登録済み** なら、照合のエラーで所在不明にした2つに加えて、**交換後の消耗品も所在不明** にします。人の確認を必須にします。
- 人が現物を交換したとき、交換後の ID が **未登録** なら、その消耗品は使わずに、**AGV でステーションへ回収** し、不明な消耗品として置きます。装置には、ステーションから **別の消耗品を届けます**（そのスロットは不足として扱い、搬送計画がいつもどおり届けます）。
- 照合のエラーや、交換後の不整合（未登録の ID など）があったときは、その消耗品をステーションへ回収する搬送を、**システムが自動で頼みます**。
  - 回収の理由に **「不整合」** を加え、ほかの回収と同じように、搬送計画が頼みます。不整合は、スロットをふさいで生産を止めかねないので、**回収の中で一番先に** 積みます（不整合、設定にない品種、設定より多い品種、廃棄の順）。
  - 人が交換して、交換後の消耗品が **登録済み** だったときも、不整合として回収します（ステーションで現物を確かめるため）。
  - 読み取った ID や交換後の ID が **未登録** だと、品種も加工の種類もわかりません。運ぶキャリアは、**記録上そのスロットにあった消耗品の加工の種類** で決めます。記録上何もなかったら、その装置の設定にある加工の種類が1つだけならそれを使い、そうでなければエラーにします。
  - 回収した不整合の消耗品には、ステーションで **「要確認」** の印を付け、届けるものの候補から外します。
  - そのスロットが空いたら、不足として、搬送計画が別の消耗品を届けます。
  - 届ける消耗品をユーザーが選びたいときは、AGV を使って受け渡す流れ（画面からの指示）を使います。
- 現物はあるのに記録上は所在不明の消耗品が置かれたスロットは、人が確かめて直すか、AGV で回収するまで、**ふさがっているもの** として数えます（届けるものの入れ先にしません）。
- AGV を使って受け渡すときは、次のようにします。
  - **ユーザーが画面から指示** し、届ける消耗品の **ID を選びます**。
  - **回収を先に** 行います。回収の許可で、取り出すスロットを指示します。そのあと、選んだ消耗品を届けます。
  - 回収は、照合のエラーで自動で頼む回収をそのまま使います。ユーザーの指示は、**届ける消耗品の指名** として扱います。
    - 指示するのは、**装置と、届ける消耗品の ID** だけです（照合のエラーやスロットとは結び付けません）。
    - 指名できるのは、**ステーションにある、要確認でない新品** です。届ける予約が付いているもの、出庫を頼んだものは指名できません。
    - **すでに指名されている消耗品** は、もう一度は指名できません。別の装置へ変えるときは、取り消してから指名し直します。
    - 指名があれば、その装置の不足を補うときに、**先入れ先出しより先に、指名された消耗品を使います**。ほかの装置へは届けません。
    - 指名した消耗品の品種が、その装置で **不足していなければ、不足が出るまで待ちます**（照合のエラーの回収が終わると、そのスロットのぶんが不足になります）。
    - 「回収が先」は、ストッカーが満杯のまま届けて詰まらないようにするためです。このため、**空きスロットがあれば、回収を待たずに届けます**（いつもの「空きの数までしか届けない」と同じです）。
    - 入れるスロットは、いつもどおり、**空いているうち番号が一番小さいスロット** です。
    - 必要時刻は、いつもの不足と同じく、**不足を見つけた時刻** です。
    - 指名は、**割り当て前なら取り消せます**。取り消したら、いつもどおり先入れ先出しで選びます。
    - 指名された消耗品が、ステーションにある要確認でない新品でなくなったら（要確認になった、出庫を頼んだ、積み込んだなど）、**指名は自動で外れます**。

- 所在不明にした消耗品に、搬送の予約（回収など）が付いていたら、**予約を解き**、不足と回収の判断をやり直します。

## 消耗品の在庫管理

- 消耗品が **どこにあるか** と **何個あるか** を把握する在庫管理は、このシステムの責務です。
- ステーションからシステムの外に出た消耗品は、**在庫管理の対象から外れます**。
- ユーザーは、画面から在庫情報を **手入力** で登録・修正でき、**削除** もできます。
  - ただし、搬送中の消耗品など、編集すると不整合が起きるものは **編集・削除できません**。
- ステーションからの取り出し（出庫）は、**人が任意のタイミングで行う** か、**上位システムの指示で行います**。
  - 出庫したら、ステーションが **出た ID** を知らせてきます。システムは、その消耗品を **記録から消します**。付いていた予約は解き、不足と回収の判断をやり直します。
    - 記録上そのステーションになかった消耗品も、知らせを正として記録から消し、食い違いをログに残して画面で警告します。**未登録の ID** の知らせは、食い違いとして警告するだけにします。
  - 上位システムの指示で出すときは、ステーションに出庫を頼みます。出たら、上と同じ知らせが来ます。
    - 記録上 **ステーションにない消耗品** の出庫の指示は、受け付けません。
  - 届ける予約が付いている消耗品の出庫の指示は、**予約を解いて出します**。ただし、その搬送に **AGV が割り当て済みなら、受け付けません**。
- 画面からの在庫の手入力（登録・修正・削除）は、画面に取りかかるときに作ります。
